# DB 사용량 절감 적용 범위

- 창고 자동 조회: 같은 계정의 성공한 서버 조회를 30초간 재사용한다.
- 동시에 발생한 자동 조회는 하나의 진행 중 요청을 공유한다.
- 명시적인 강제 조회와 아이템 획득 후 조회는 캐시를 우회한다.
- 계정 mount 시 캐시 유효기간과 진행 중 요청을 초기화한다. 디스크 캐시만으로 소유권을 승인하지 않는다.
- 변경 없는 미니홈 저장은 서버를 호출하지 않는다. 실패한 저장의 멱등성 재시도와 충돌 해결은 유지한다.
- 서버 창고 조회/획득 시 기존 generation/hash와 동일한 inventoryState 재쓰기를 생략한다. 서버 검증과 실제 변경 기록은 유지한다.

## 절감 효과와 한계

30초 내 반복 창고 진입은 추가 조회를 생략한다. 실제 서버 조회에서는 기존 카탈로그/소유 아이템/식물 읽기가 여전히 발생한다. 같은 상태 재조회당 inventoryState 쓰기 1회를 줄인다. 미니홈 변경 없는 저장은 해당 호출 전체를 생략한다.

다른 기기 변경은 자동 조회 캐시 기간 동안 늦게 보일 수 있다. 권한과 획득 조건은 서버에서 계속 검증한다. 카탈로그 집계 문서, 식물 수 요약 문서, 광범위한 동기화 구조 변경은 이번 범위에 포함하지 않았다. 운영 배포 전 실제 Firestore 에뮬레이터 회귀 검증이 필요하다.

## Android 전달

Plant Diary의 `Android App 개발` 작업에 동일한 원칙을 전달했다. Android 구현 완료를 의미하지 않는다. 공유 백엔드 중복 편집을 피하고 기존 Android 승인/검증 단계를 유지하도록 요청했다.
