## 1. 프로젝트 개요
---
### 한 줄 정의
초보 식집사를 위한 식물 식별·관리·수집형 모바일 앱

### 제품 목표
사용자가 식물 사진만으로 식물 종류를 쉽게 확인하고, 개인 도감에 등록한 뒤 물 주기, 빛, 온도·습도, 증상 대처법을 이해하도록 돕는다. 식물별 관리 시점을 알림으로 안내하여 초보자도 꾸준한 관리 습관을 형성하고 식물을 건강하게 키울 수 있도록 한다. 또한 등록한 식물을 미니어처 형태로 미니홈피에 꾸미고 공유하게 하여 식물 관리의 지속적인 참여와 즐거움을 제공한다.

### 배경
홈 플랜팅을 시작하는 초보자는 자신이 키우는 식물의 이름과 종류를 파악하기 어렵고, 식물별 물 주기와 생육 환경을 정확히 알기 힘들다. 관리 시기를 놓치거나 과도하게 물을 주는 문제, 계절과 날씨 변화에 따른 온도·습도 관리 부족으로 식물을 건강하게 키우지 못하는 경우가 많다. 기존 식물 정보 서비스는 전문 정보가 많아 초보자가 이해하기 어렵거나, 식별·관리 일정·꾸미기 기능이 분리되어 있다. 초보 식집사는 식물 식별부터 일상적인 관리, 수집과 꾸미기까지 한 곳에서 경험할 수 있는 쉽고 친근한 서비스가 필요하다.

### 사용자 문제
초보 식집사는 사진 속 식물의 이름을 알기 어렵고, 식물별 물 주기·햇빛·온도·습도 조건을 판단하기 어렵다. 관리해야 할 시기를 기억하지 못하거나 날씨 변화에 적절히 대응하지 못해 식물이 시들거나 생육이 저하될 수 있다. 또한 식물을 관리하면서 얻은 성취감을 기록하고 즐길 수 있는 요소가 부족하다.

### 해결 방안
카메라로 촬영한 식물을 이미지 분석으로 식별하고, 식별 결과를 사용자가 확인·수정한 뒤 개인 도감에 등록할 수 있도록 한다. 직접 등록도 지원하여 식별이 어려운 식물이나 사용자가 이미 알고 있는 식물도 관리할 수 있게 한다. 도감에서는 식물별 물 주기, 햇빛, 적정 온도·습도, 주요 증상과 대처법을 제공하고, 물 주기 도래 알림과 날씨 기반 관리 주의 알림을 제공한다. 등록 식물은 미니어처로 변환하여 미니홈피에 배치할 수 있으며, 꾸미기 아이템 창고와 상점을 통해 수집과 선택적 공유를 지원한다.

### 차별점
식물 식별, 개인 식물 도감, 맞춤형 관리 알림, 날씨 기반 주의 안내, 미니홈피 꾸미기를 하나의 경험으로 연결한다. 전문 용어 중심의 식물 정보가 아니라 초보자가 바로 실행할 수 있는 간단한 관리 행동 중심으로 정보를 제공하며, 식물별 일정과 지역 날씨를 함께 고려한다. 관리 활동을 미니어처 수집과 공간 꾸미기로 연결해 단순 정보 앱보다 높은 재방문 동기와 정서적 만족을 제공한다.

### 타겟 사용자
20~40대의 홈 플랜팅 입문자. 최근 온라인이나 오프라인에서 반려식물을 구매했지만 식물 이름과 관리법을 정확히 모르는 사람이다. 식물 관리 경험이 적어 물 주기와 햇빛 조건을 자주 헷갈리며, 바쁜 일상 때문에 관리 시기를 놓치기 쉽다. 전문적인 식물 지식보다 짧고 쉬운 설명과 알림을 선호하고, 자신의 식물 성장 과정을 기록하거나 아기자기하게 꾸미고 공유하는 활동에 관심이 있다. 초기에는 식물 식별과 관리 성공을 가장 중요하게 생각하지만, 사용이 익숙해지면 도감 완성과 미니홈피 꾸미기에도 참여할 가능성이 높다.

### 사용자 시나리오
사용자는 새로 구매한 식물을 앱의 카메라로 촬영한다. 앱은 식물 후보와 식별 신뢰도를 보여주고, 사용자는 결과를 확인하거나 재촬영·직접 수정하여 식물을 등록한다. 등록이 완료되면 개인 도감에 식물이 추가되고, 해당 식물의 물 주기, 햇빛, 온도·습도, 증상 대처 정보를 확인한다. 사용자는 식물의 위치와 마지막 물 주기일을 설정하고, 관리 예정일에 알림을 받는다. 날씨가 급격히 덥거나 건조해지면 앱에서 환기, 분무, 위치 이동 등 주의 행동을 안내한다. 관리가 끝난 뒤 사용자는 미니홈피에서 등록 식물을 미니어처로 배치하고 꾸미기 아이템을 적용하며, 완성된 공간을 선택적으로 공유한다.

### 핵심 지표
핵심 성과 지표는 신규 사용자 식물 등록 완료율, 첫 식물 식별 성공률, 식물 식별 결과 수정·확정률, 식물별 관리 정보 조회율, 물 주기 알림 확인율, 알림 후 관리 완료율, 7일 및 30일 재방문율, 사용자당 등록 식물 수, 미니홈피 꾸미기 참여율, 꾸미기 결과 공유율이다. 초기 목표 예시는 첫 식물 등록 완료율 70% 이상, 사진 식별 결과 확정률 80% 이상, 물 주기 알림 확인율 60% 이상, 30일 재방문율 25% 이상으로 설정할 수 있다.

### 리스크
사진 품질이나 유사 품종으로 인해 식물 식별 결과가 부정확할 수 있다. 잘못된 물 주기나 환경 정보는 식물 손상으로 이어질 수 있으므로 정보 출처와 최신성을 관리해야 한다. 날씨 API 장애나 위치 정보 오류로 부정확한 환경 알림이 제공될 수 있다. 알림이 지나치게 많으면 사용자가 피로를 느끼고 알림을 끌 수 있다. 미니홈피와 상점 기능이 핵심 관리 기능보다 강조되면 서비스의 본래 가치가 약화될 수 있다. 사용자 식물 사진과 위치 정보의 수집·보관에 따른 개인정보 보호 이슈도 존재한다.

## 1. 식물 사진 식별 및 등록
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

사용자가 카메라 또는 사진 보관함으로 식물 사진을 제출하면 식물 종류 후보를 제공한다. 식별 결과에는 식물명과 신뢰도 또는 후보 목록을 표시하고, 사용자가 결과를 확정하거나 재촬영·직접 수정하여 등록할 수 있어야 한다. 사진 식별이 어려운 경우에도 식물명 검색 또는 직접 입력을 통해 등록할 수 있어야 한다.

**수용 기준:**
```
1. ○ 사용자가 카메라 촬영 또는 사진 보관함 선택으로 식별을 시작할 수 있다.
2. ○ 식별 결과에 하나 이상의 식물 후보와 식별 신뢰도 또는 결과 안내가 표시된다.
3. ○ 사용자가 식별 결과를 확정하거나 재촬영할 수 있다.
4. ○ 사용자가 식물명과 기본 정보를 직접 입력하거나 식별 결과를 수정하여 등록할 수 있다.
5. ○ 등록 완료 후 해당 식물이 개인 도감과 관리 대상 목록에 즉시 표시된다.
6. ○ 식별 실패 시 실패 원인과 재촬영·직접 등록 등 대체 경로가 안내된다.
```


### 1.1 식물 사진 촬영 및 선택
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

일반 사용자가 모바일 앱에서 카메라로 식물을 촬영하거나 사진 보관함의 이미지를 선택하여 식별 요청을 시작하는 기능이다. 제출할 사진을 확인하고 다시 선택 또는 재촬영할 수 있도록 하며, 식물 식별 요청에 필요한 이미지 입력 단계까지만 포함한다. 식별 후보 분석과 등록 확정은 이 기능의 범위에 포함하지 않는다.

**개발 준비 슬롯**
- **선행조건**: - 사용자가 모바일 앱에서 식물 식별 기능에 접근한다.
  - 카메라 촬영을 사용하는 경우 앱에 카메라 접근 권한이 필요하다.
- **트리거**: - 사용자가 식물 식별 시작 버튼을 선택한다.
- **동작**: - 사용자는 카메라로 식물 사진을 촬영하거나 사진 보관함에서 사진을 선택한다.
  - 사용자는 제출 전에 선택한 사진을 확인하고 재촬영하거나 다른 사진으로 변경할 수 있다.
  - 앱은 사용자가 제출한 사진을 식별 분석 단계로 전달한다.
- **결과**: - 식별 분석에 사용할 식물 사진이 준비되어 식별 결과 화면으로 이동한다.
- **예외**: - 카메라 권한이 없으면 권한 필요 사유와 기기 설정에서 권한을 허용하는 방법을 안내한다.
  - 사진 선택 또는 업로드에 실패하면 다시 시도할 수 있도록 안내한다.
- **표시**: - 식별 시작 화면에는 카메라 촬영과 사진 보관함 선택 진입 버튼을 표시한다.
  - 사진 확인 화면에는 선택한 사진과 재촬영 또는 사진 변경 버튼을 표시한다.
- **권한 & 접근**: - 카메라 촬영은 사용자 동의에 따른 카메라 접근 권한을 사용한다.
  - 사진 보관함 접근은 사용자 동의에 따른 기기 사진 접근 권한을 사용한다.
- **비즈니스 규칙**: - 사용자가 사진 제출을 확정하기 전에는 식별 분석을 시작하지 않는다.
  - 사진 입력 권한을 거부해도 사용자는 직접 등록 경로를 이용할 수 있다.
- **데이터**: - 식별 요청에는 선택 또는 촬영한 식물 사진과 요청 상태를 저장한다.


#### 1.1.1 카메라로 식물 사진 촬영

일반 사용자가 모바일 앱의 식물 식별 시작 화면에서 기기 카메라를 열어 식물 사진을 촬영하는 기능이다. 촬영한 사진은 제출 전 확인 단계로 전달되며, 사용자는 만족할 때까지 다시 촬영할 수 있다. 이 기능은 사진 보관함 선택 및 식물 식별 분석 결과 제공을 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 모바일 앱의 식물 식별 시작 화면에 접근한다.
  - 사용자가 앱의 카메라 접근 권한을 허용한다.
- **트리거**: - 사용자가 식별 시작 화면에서 카메라 촬영을 선택한다.
- **동작**: - 앱은 기기 카메라를 실행해 식물을 촬영할 수 있게 한다.
  - 사용자는 촬영한 사진을 확인하거나 다시 촬영할 수 있다.
  - 앱은 사용자가 채택한 촬영 사진을 사진 검토 및 제출 단계로 전달한다.
- **결과**: - 사용자가 촬영한 식물 사진이 식별 요청을 위한 검토 대상으로 준비된다.
- **예외**: - 카메라 접근 권한이 없거나 거부되면 권한 필요 사유와 기기 설정에서 권한을 허용하는 방법을 안내한다.
  - 카메라 실행 또는 촬영에 실패하면 다시 시도할 수 있도록 안내하고 사진 보관함 선택 경로를 제공한다.
- **표시**: - 식별 시작 화면에는 카메라 촬영 진입 버튼을 표시한다.
  - 촬영 화면에는 촬영 버튼과 닫기 버튼을 표시한다.
  - 촬영 후 확인 화면에는 촬영 사진, 다시 촬영 버튼, 사진 사용 버튼을 표시한다.
- **권한 & 접근**: - 카메라 촬영은 사용자의 명시적 동의에 따른 기기 카메라 접근 권한을 사용한다.
- **비즈니스 규칙**: - 카메라 권한을 거부한 사용자는 권한을 허용하지 않아도 사진 보관함 선택 또는 직접 등록 경로를 이용할 수 있다.
  - 사용자가 사진 사용을 확정하기 전에는 촬영 사진을 식별 분석에 제출하지 않는다.
- **데이터**: - 촬영 사진 데이터에는 임시 사진 참조값, 촬영 방식, 선택 상태를 저장한다.


#### 1.1.2 사진 보관함에서 식물 사진 선택

일반 사용자가 모바일 기기의 사진 보관함에서 기존 식물 사진을 선택하여 식별 요청을 준비하는 기능이다. 선택한 사진은 제출 전에 확인 및 변경할 수 있으며, 사용자가 채택한 사진만 다음 제출 단계로 전달한다. 이 기능은 카메라 촬영과 식별 후보 분석을 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 모바일 앱의 식물 식별 시작 화면에 접근한다.
  - 사용자가 기기 사진 접근 권한을 허용하거나 운영체제가 제공하는 사진 선택기를 사용할 수 있다.
- **트리거**: - 사용자가 식별 시작 화면에서 사진 보관함 선택을 선택한다.
- **동작**: - 앱은 사용자가 기기 사진 보관함에서 식물 사진을 선택할 수 있게 한다.
  - 사용자는 선택한 사진을 확인하고 다른 사진으로 변경할 수 있다.
  - 앱은 사용자가 채택한 사진을 사진 검토 및 제출 단계로 전달한다.
- **결과**: - 사용자가 선택한 식물 사진이 식별 요청을 위한 검토 대상으로 준비된다.
- **예외**: - 사진 접근 권한이 없거나 거부되면 권한 필요 사유와 기기 설정에서 권한을 허용하는 방법을 안내한다.
  - 사진 선택에 실패하면 다시 선택할 수 있도록 안내하고 카메라 촬영 경로를 제공한다.
- **표시**: - 식별 시작 화면에는 사진 보관함 선택 진입 버튼을 표시한다.
  - 사진 선택 후 확인 화면에는 선택한 사진, 사진 변경 버튼, 사진 사용 버튼을 표시한다.
- **권한 & 접근**: - 사진 보관함 선택은 사용자의 명시적 동의에 따른 기기 사진 접근 권한 또는 운영체제 사진 선택 권한을 사용한다.
- **비즈니스 규칙**: - 사용자가 사진 사용을 확정하기 전에는 선택한 사진을 식별 분석에 제출하지 않는다.
  - 사진 접근 권한을 거부한 사용자는 카메라 촬영 또는 직접 등록 경로를 이용할 수 있다.
- **데이터**: - 선택 사진 데이터에는 임시 사진 참조값, 선택 방식, 선택 상태를 저장한다.


#### 1.1.3 식별 사진 검토 및 분석 요청 제출

일반 사용자가 카메라로 촬영하거나 사진 보관함에서 선택한 식물 사진을 최종 확인한 뒤 식별 분석 요청을 제출하는 기능이다. 사용자는 제출 전 사진을 교체하거나 이전 단계로 돌아갈 수 있으며, 명시적으로 제출한 사진만 식별 결과 확인 기능으로 전달된다. 이 기능은 식별 후보의 표시와 확정을 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 카메라 촬영 또는 사진 보관함 선택으로 식별할 식물 사진을 준비한다.
- **트리거**: - 사용자가 사진 확인 화면에서 식별 요청 제출을 선택한다.
- **동작**: - 앱은 사용자가 제출할 식물 사진을 미리 보기로 표시한다.
  - 사용자는 제출 전에 사진을 다시 촬영하거나 다른 사진으로 변경할 수 있다.
  - 사용자가 제출을 확정하면 앱은 사진을 이미지 분석 서비스로 전달한다.
- **결과**: - 식별 분석 요청이 생성되고 식별 결과 대기 또는 결과 확인 화면으로 이동한다.
- **예외**: - 사진 업로드 또는 식별 요청 생성에 실패하면 실패 상태와 다시 시도 방법을 안내한다.
  - 제출 가능한 사진이 없으면 식별 요청을 진행하지 않고 사진 촬영 또는 선택을 요청한다.
- **표시**: - 사진 확인 화면에는 제출 대상 사진과 사진 변경 또는 재촬영 버튼을 표시한다.
  - 사진 확인 화면에는 식별 요청 제출 버튼과 이전 단계로 돌아가는 버튼을 표시한다.
  - 분석 요청 중에는 진행 상태를 표시하고 중복 제출을 방지한다.
- **권한 & 접근**: - 사진 검토 및 분석 요청 제출에는 별도의 추가 기기 권한이 필요하지 않다.
- **비즈니스 규칙**: - 사용자가 식별 요청 제출을 명시적으로 선택한 경우에만 이미지 분석을 시작한다.
  - 분석 요청이 진행 중인 동일 사진은 중복 제출하지 않는다.
- **데이터**: - 식별 요청 데이터에는 요청 식별자, 임시 사진 참조값, 사진 입력 방식, 요청 생성 시각, 분석 요청 상태를 저장한다.


### 1.2 식별 후보 확인 및 결과 확정
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

일반 사용자가 이미지 분석으로 받은 식물 후보, 식물명, 식별 신뢰도 또는 결과 안내를 확인하고 적절한 결과를 확정하는 기능이다. 사용자는 후보가 맞지 않을 때 재촬영 또는 직접 수정 경로로 이동할 수 있으며, 확정된 식물 정보를 개인 도감 등록 단계로 전달한다. 식물의 관리 정보 편집은 이 기능의 범위에 포함하지 않는다.

**개발 준비 슬롯**
- **선행조건**: - 사용자가 식별할 식물 사진을 제출한다.
  - 이미지 분석 서비스가 식별 결과 또는 실패 상태를 반환한다.
- **트리거**: - 식물 사진의 이미지 분석이 완료된다.
- **동작**: - 앱은 하나 이상의 식물 후보와 각 후보의 식물명 및 식별 신뢰도 또는 결과 안내를 표시한다.
  - 사용자는 후보를 선택하여 식별 결과를 확정한다.
  - 사용자는 결과가 부정확하다고 판단하면 재촬영하거나 직접 수정 또는 직접 등록으로 전환한다.
- **결과**: - 사용자가 확정한 식물명과 식별 결과가 등록 단계로 전달된다.
  - 사용자가 결과를 확정한 사실을 기록한다.
- **예외**: - 식별 후보를 제공하지 못하면 식별 실패 원인을 안내한다.
  - 식별 실패 시 재촬영과 직접 등록의 대체 경로를 제공한다.
- **표시**: - 결과 화면에는 제출한 사진, 식물 후보 목록, 식물명, 신뢰도 또는 결과 안내를 표시한다.
  - 결과 화면에는 확정, 재촬영, 직접 수정 또는 직접 등록 버튼을 표시한다.
- **권한 & 접근**: - 식별 결과 확인과 확정은 일반 사용자가 수행할 수 있다.
- **비즈니스 규칙**: - 사용자가 식별 결과를 확정하거나 직접 입력한 식물명을 확인해야 등록 단계로 진행할 수 있다.
  - 식별 신뢰도가 낮거나 식별에 실패한 경우에도 직접 등록 경로를 차단하지 않는다.
- **데이터**: - 식별 결과에는 제출 사진 참조값, 후보 식물명, 후보별 신뢰도 또는 결과 안내, 사용자의 확정 또는 수정 상태를 저장한다.


#### 1.2.1 식별 후보와 신뢰도 확인

일반 사용자가 제출한 식물 사진의 분석 결과에서 식물 후보와 후보별 식별 신뢰도 또는 결과 안내를 확인하는 기능이다. 사용자는 제출한 사진을 함께 보며 후보를 비교할 수 있고, 후보 선택이나 대체 경로로 이동하기 전 결과를 이해한다. 후보 확정과 직접 등록 자체는 이 기능의 범위에 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 식물 사진을 식별 분석 요청으로 제출한다.
  - 이미지 분석 서비스가 식별 후보 또는 분석 결과 상태를 반환한다.
- **트리거**: - 식물 사진의 이미지 분석이 완료되어 결과를 수신한다.
- **동작**: - 앱은 제출한 식물 사진과 식별 후보 목록을 표시한다.
  - 앱은 각 후보의 식물명과 식별 신뢰도 또는 신뢰 수준을 표시한다.
  - 사용자는 후보별 정보를 확인한 뒤 확정할 후보를 선택하거나 대체 경로를 선택한다.
- **결과**: - 사용자는 식별 결과를 비교하고 다음 행동을 결정할 수 있다.
  - 시스템은 식별 결과 조회 이벤트를 기록한다.
- **예외**: - 분석 결과 수신이 지연되면 분석 진행 상태를 표시한다.
  - 분석 서비스 오류가 발생하면 결과를 제공할 수 없음을 안내하고 재시도 또는 직접 등록 경로를 제공한다.
- **표시**: - 결과 화면에는 제출한 사진, 식물 후보 목록, 후보별 식물명과 신뢰도 또는 결과 안내를 표시한다.
  - 결과 화면에는 후보 확정, 재촬영, 직접 수정 또는 직접 등록으로 이어지는 버튼을 표시한다.
- **권한 & 접근**: - 일반 사용자는 본인이 제출한 식별 요청의 결과만 조회할 수 있다.
- **비즈니스 규칙**: - 후보 목록은 이미지 분석 서비스가 반환한 신뢰도 순서에 따라 표시한다.
  - 후보 수와 표시 기준은 식별 결과 기능의 공통 설정을 따른다.
  - 식별 신뢰도는 식물 종류를 확정하는 진단 정보가 아니라 후보 선택을 돕는 참고 정보로 제공한다.
- **데이터**: - 식별 결과 데이터에는 요청 식별자, 제출 사진 참조값, 후보 식물 식별자 또는 식물명, 후보별 신뢰도, 분석 완료 시각, 결과 상태를 저장한다.


#### 1.2.2 식별 후보 선택 및 등록 정보 확정

일반 사용자가 식별 결과에서 적절한 식물 후보를 선택하고 해당 식물명으로 등록 정보를 확정하는 기능이다. 확정한 식물과 식별 결과 상태를 개인 도감 등록 단계로 전달하여 이후 등록을 이어갈 수 있게 한다. 신규 식물 정보를 직접 입력하여 등록하는 기능은 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 식별 결과 화면에서 하나 이상의 식물 후보를 확인한다.
- **트리거**: - 사용자가 식별 후보를 선택하고 결과 확정을 요청한다.
- **동작**: - 사용자는 식별 후보 중 하나를 선택한다.
  - 사용자는 선택한 후보의 식물명을 확인하고 식별 결과를 확정한다.
  - 시스템은 확정한 식물 정보를 개인 도감 등록 단계로 전달한다.
- **결과**: - 확정한 식물명과 식별 등록 방식이 등록 단계에 전달된다.
  - 시스템은 후보 선택과 식별 결과 확정 이벤트를 기록한다.
- **예외**: - 사용자가 후보를 선택하지 않으면 식별 결과 확정을 진행하지 않고 후보 선택을 안내한다.
  - 식별 결과 저장에 실패하면 확정이 완료되지 않았음을 안내하고 다시 시도할 수 있게 한다.
- **표시**: - 선택한 후보는 다른 후보와 구분되도록 표시한다.
  - 결과 화면에는 선택 후보를 확정하는 버튼과 이전 결과 선택으로 돌아가는 버튼을 표시한다.
  - 확정 후에는 개인 도감 등록 단계로 이어짐을 안내한다.
- **권한 & 접근**: - 일반 사용자는 본인이 제출한 식별 결과만 확정할 수 있다.
- **비즈니스 규칙**: - 사용자가 하나의 후보를 명시적으로 확정해야 식별 결과 기반 등록 단계로 진행할 수 있다.
  - 확정된 후보는 사진 식별 확정 방식으로 기록한다.
  - 식별 결과 확정만으로 개인 도감 등록을 완료 처리하지 않는다.
- **데이터**: - 식별 확정 데이터에는 요청 식별자, 선택한 후보 식별자 또는 식물명, 후보 신뢰도, 확정 상태, 확정 시각, 등록 방식 정보를 저장한다.


#### 1.2.3 식별 결과 불일치 및 실패 대체 경로 안내

일반 사용자가 식별 후보가 실제 식물과 다르다고 판단하거나 분석이 실패했을 때 재촬영, 직접 수정, 직접 등록 중 다음 행동을 선택할 수 있도록 안내하는 기능이다. 식별 실패로 인해 식물 등록 흐름이 중단되지 않도록 대체 경로를 제공한다. 재촬영과 직접 등록의 상세 입력·제출 동작은 각각 별도 기능에서 처리한다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 식별 분석이 실패했거나 사용자가 표시된 후보가 적절하지 않다고 판단한다.
- **트리거**: - 사용자가 결과 화면에서 후보 없음, 재촬영, 직접 수정 또는 직접 등록을 선택한다.
  - 시스템이 식별 실패 상태를 반환한다.
- **동작**: - 앱은 식별 실패 또는 후보 불일치 사유를 사용자가 이해하기 쉬운 문장으로 안내한다.
  - 사용자는 식물 사진을 다시 촬영하거나 사진을 다시 선택하는 경로로 이동할 수 있다.
  - 사용자는 식물명을 직접 수정하거나 직접 등록 경로로 이동할 수 있다.
- **결과**: - 사용자는 식별 결과를 확정하지 않아도 재식별 또는 직접 등록을 계속 진행할 수 있다.
  - 시스템은 식별 실패와 대체 경로 선택 이벤트를 기록한다.
- **예외**: - 재식별 요청이 반복해서 실패해도 직접 등록 경로는 계속 제공한다.
  - 대체 경로 화면으로 이동하지 못하면 현재 결과 화면에서 다시 시도할 수 있게 한다.
- **표시**: - 실패 또는 불일치 안내에는 식별할 수 없거나 결과가 정확하지 않을 수 있음을 표시한다.
  - 안내 화면에는 재촬영, 사진 변경, 직접 수정, 직접 등록 버튼을 표시한다.
- **권한 & 접근**: - 일반 사용자는 본인의 식별 요청에서만 대체 경로를 선택할 수 있다.
- **비즈니스 규칙**: - 식별 신뢰도가 낮거나 식별에 실패한 경우에도 직접 등록 경로를 차단하지 않는다.
  - 사용자가 대체 경로를 선택하기 전에는 분석 실패 상태만으로 개인 도감에 식물을 등록하지 않는다.
  - 실패 안내는 전문적인 원인 추정 대신 재촬영과 직접 등록 같은 실행 가능한 다음 행동을 우선 제공한다.
- **데이터**: - 식별 실패 데이터에는 요청 식별자, 실패 상태 또는 실패 사유 코드, 안내 시각, 사용자가 선택한 대체 경로를 저장한다.


### 1.3 직접 식물명 입력 및 개인 도감 등록
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

일반 사용자가 식별 결과를 수정하거나 식별이 어려운 식물의 이름과 기본 정보를 직접 입력하여 개인 도감 및 관리 대상 목록에 등록하는 기능이다. 등록 완료 즉시 사용자의 식물 목록에서 해당 식물을 확인할 수 있도록 하며, 사진 식별 성공 여부와 무관하게 사용할 수 있다. 상세 관리 정보 조회와 알림 일정 설정은 후속 관리 기능의 범위에 포함한다.

**개발 준비 슬롯**
- **선행조건**: - 사용자가 식별 결과 화면 또는 직접 등록 진입 화면에 접근한다.
- **트리거**: - 사용자가 식별 결과를 수정하거나 직접 등록을 선택한다.
- **동작**: - 사용자는 식물명을 검색하거나 직접 입력한다.
  - 사용자는 등록에 필요한 기본 정보를 입력하거나 확인한다.
  - 사용자는 입력 내용을 확인한 뒤 개인 도감 등록을 완료한다.
- **결과**: - 등록 완료 후 해당 식물이 개인 도감과 관리 대상 목록에 즉시 표시된다.
  - 사용자가 입력하거나 확정한 식물 정보가 개인 식물 기록으로 저장된다.
- **예외**: - 필수 정보가 누락되면 누락된 입력 항목과 보완 방법을 안내한다.
  - 식물명 검색 결과가 없으면 식물명을 직접 입력하여 등록할 수 있도록 한다.
- **표시**: - 직접 등록 화면에는 식물명 검색 또는 직접 입력 필드와 등록 완료 버튼을 표시한다.
  - 등록 완료 화면에는 새로 추가된 식물과 개인 도감으로 이동하는 안내를 표시한다.
- **권한 & 접근**: - 일반 사용자는 자신의 개인 도감에 식물을 등록하고 수정할 수 있다.
- **비즈니스 규칙**: - 직접 등록은 사진 식별 결과가 없는 경우와 식별 결과를 수정하는 경우 모두 지원한다.
  - 등록이 완료된 식물은 개인 도감과 관리 대상 목록에 동일하게 반영한다.
- **데이터**: - 개인 식물 기록에는 사용자 식별자, 식물명, 식별 등록 방식, 선택적으로 연결된 사진 참조값과 기본 입력 정보를 저장한다.
  - 식별 등록 방식은 사진 식별 확정, 식별 결과 수정, 직접 입력 중 하나로 기록한다.


#### 1.3.1 직접 등록용 식물명 검색 및 선택

일반 사용자가 직접 등록 화면에서 식물명을 검색해 제공되는 식물 콘텐츠와 연결할 대상을 선택하는 기능이다. 검색 결과가 없거나 원하는 식물이 없으면 사용자는 직접 식물명을 입력하는 흐름으로 전환할 수 있다. 이 기능은 식물의 개인 관리 정보 저장과 등록 완료 처리를 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 식별 결과 화면 또는 직접 등록 화면에서 직접 등록을 시작한다.
- **트리거**: - 사용자가 식물명 검색 입력란을 선택하거나 검색어를 입력한다.
- **동작**: - 사용자는 식물명을 입력하여 등록 가능한 식물 콘텐츠를 검색한다.
  - 시스템은 입력한 검색어와 일치하거나 유사한 식물명 결과를 제공한다.
  - 사용자는 검색 결과 중 하나를 선택하거나 직접 입력 방식으로 전환한다.
- **결과**: - 선택한 식물 콘텐츠의 식물명과 연결 정보가 등록 입력 단계로 전달된다.
  - 검색 결과가 없는 식물도 직접 식물명 입력을 통해 등록할 수 있다.
- **예외**: - 검색어와 일치하는 결과가 없으면 검색 결과가 없음을 안내하고 직접 입력 경로를 제공한다.
  - 검색 결과 조회에 실패하면 실패 상태와 다시 시도 방법을 안내한다.
- **표시**: - 직접 등록 화면에는 식물명 검색 입력란과 직접 입력 전환 버튼을 표시한다.
  - 검색 결과에는 식물명과 사용자가 식물을 구분할 수 있는 대표 정보를 표시한다.
  - 검색 결과가 없을 때는 직접 식물명 입력을 유도하는 안내를 표시한다.
- **권한 & 접근**: - 일반 사용자는 식물 콘텐츠를 검색하여 자신의 개인 도감 등록 대상으로 선택할 수 있다.
- **비즈니스 규칙**: - 공개 상태인 식물 관리 콘텐츠만 검색 결과와 선택 대상으로 제공한다.
  - 사용자가 검색 결과를 선택하지 않아도 직접 식물명 입력 방식으로 등록을 계속할 수 있다.
- **데이터**: - 검색 데이터에는 검색어, 조회 시각, 검색 결과 식물 식별자와 식물명을 포함한다.
  - 선택 데이터에는 사용자가 선택한 식물 콘텐츠 식별자와 선택 방식을 저장한다.


#### 1.3.2 식물명 및 기본 정보 직접 입력

일반 사용자가 검색 결과를 선택하지 않거나 식별 결과를 수정할 때 식물명과 등록에 필요한 기본 정보를 직접 입력하는 기능이다. 입력값의 필수 여부와 형식을 검증하여 개인 식물 기록으로 저장할 수 있는 등록 정보를 준비한다. 개인 도감 등록 완료와 관리 일정 계산은 이 기능의 범위에 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 직접 등록 화면에 접근한다.
- **트리거**: - 사용자가 식물명 직접 입력을 선택하거나 식별 결과의 식물명을 수정한다.
- **동작**: - 사용자는 식물명을 직접 입력하거나 식별 결과로 제안된 식물명을 수정한다.
  - 사용자는 선택적으로 식물 사진과 기본 관리 정보를 입력한다.
  - 시스템은 필수 입력값과 입력 형식을 확인한다.
- **결과**: - 유효한 식물명과 기본 입력 정보가 개인 도감 등록 확인 단계로 전달된다.
  - 식별 결과를 수정한 경우 수정된 식물명이 등록 대상 정보로 반영된다.
- **예외**: - 필수 입력값이 누락되면 누락된 항목과 보완 방법을 안내한다.
  - 허용되지 않은 형식의 입력값이 있으면 저장을 진행하지 않고 수정 방법을 안내한다.
- **표시**: - 직접 입력 화면에는 식물명 입력란, 선택 입력 항목, 등록 진행 버튼을 표시한다.
  - 식별 결과를 수정하는 경우에는 기존에 제안된 식물명을 편집 가능한 값으로 표시한다.
  - 입력 오류가 발생한 항목에는 오류 사유를 함께 표시한다.
- **권한 & 접근**: - 일반 사용자는 자신의 개인 도감에 추가할 식물 정보를 입력하거나 수정할 수 있다.
- **비즈니스 규칙**: - 직접 입력 식물명은 사진 식별 성공 여부와 관계없이 등록 대상으로 사용할 수 있다.
  - 직접 입력한 식물명에는 표준 식물 콘텐츠가 연결되지 않을 수 있음을 사용자에게 안내한다.
- **데이터**: - 등록 입력 정보에는 사용자 식별자, 식물명, 선택적으로 식물 사진 참조값과 마지막 물 주기일을 저장한다.
  - 식별 등록 방식은 식별 결과 수정 또는 직접 입력으로 기록한다.


#### 1.3.3 개인 도감 등록 완료 및 중복 처리

일반 사용자가 확인한 식물 정보를 자신의 개인 도감과 관리 대상 목록에 등록하고 등록 결과를 확인하는 기능이다. 등록 성공 시 식물은 즉시 목록에서 조회할 수 있으며, 같은 식물의 중복 등록 가능 여부를 안내한다. 상세 관리 정보 조회와 알림 설정은 등록 완료 후 별도 기능에서 제공한다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 식물명과 등록에 필요한 기본 정보를 입력하거나 확인한다.
  - 사용자가 개인 도감 등록을 실행할 수 있는 로그인 상태이다.
- **트리거**: - 사용자가 등록 정보 확인 화면에서 개인 도감 등록 완료를 선택한다.
- **동작**: - 시스템은 입력 또는 선택한 식물 정보로 개인 식물 기록을 생성한다.
  - 시스템은 등록한 식물을 개인 도감과 관리 대상 목록에 반영한다.
  - 시스템은 등록 결과와 다음에 할 수 있는 관리 행동을 사용자에게 안내한다.
- **결과**: - 등록 완료 후 해당 식물이 개인 도감과 관리 대상 목록에 즉시 표시된다.
  - 사용자는 등록한 식물의 상세 관리 정보 화면으로 이동할 수 있다.
  - 시스템은 식물 등록 완료 이벤트를 기록한다.
- **예외**: - 등록 저장에 실패하면 입력한 정보를 가능한 한 유지하고 실패 상태와 다시 시도 방법을 안내한다.
  - 동일 식물로 판단되는 기존 개인 기록이 있으면 중복 등록 처리 방식을 안내한다.
- **표시**: - 등록 확인 화면에는 등록할 식물명과 입력한 기본 정보를 표시한다.
  - 등록 완료 화면에는 새로 추가된 식물과 개인 도감 또는 관리 정보로 이동하는 버튼을 표시한다.
  - 중복 가능성이 있는 경우 기존 등록 식물과 중복 처리 선택지를 표시한다.
- **권한 & 접근**: - 일반 사용자는 자신의 계정에 연결된 개인 도감에만 식물을 등록할 수 있다.
- **비즈니스 규칙**: - 등록된 식물은 개인 도감과 관리 대상 목록에 동일한 개인 식물 식별자로 연결한다.
  - 등록 완료는 식물 식별 확정, 식별 결과 수정, 직접 입력 중 하나의 등록 방식을 반드시 기록한다.
  - 직접 입력한 식물은 표준 관리 콘텐츠가 없어도 개인 도감에 등록할 수 있다.
- **데이터**: - 개인 식물 기록에는 개인 식물 식별자, 사용자 식별자, 식물명, 연결된 식물 콘텐츠 식별자, 등록 방식, 사진 참조값, 등록 시각을 저장한다.
  - 등록 결과 데이터에는 등록 상태, 실패 사유, 중복 확인 여부를 포함한다.

## 2. 개인 식물 도감 및 관리 정보
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

사용자가 등록한 식물을 목록과 상세 화면에서 확인할 수 있도록 한다. 식물별 물 주기, 햇빛 요구량, 적정 온도·습도, 주요 증상과 대처법을 초보자가 이해하기 쉬운 표현으로 제공한다. 사용자는 식물별 마지막 관리일, 위치, 메모 등 관리 정보를 수정할 수 있어야 한다.

**수용 기준:**
```
1. ○ 사용자가 등록한 식물을 도감 목록에서 확인할 수 있다.
2. ○ 도감 상세 화면에 물 주기, 햇빛, 적정 온도·습도 정보가 표시된다.
3. ○ 잎 처짐, 잎 변색 등 주요 증상별 원인과 대처법을 확인할 수 있다.
4. ○ 사용자가 식물별 마지막 물 주기일과 관리 메모를 등록·수정할 수 있다.
5. ○ 식물 정보는 초보자가 이해할 수 있는 용어와 행동 중심의 문장으로 제공된다.
6. ○ 등록 식물이 없는 경우 카메라 식별 또는 직접 등록을 유도하는 안내가 표시된다.

### 2.1 등록 식물 도감 목록 조회
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

일반 사용자가 개인 도감에서 등록한 식물을 목록으로 확인하고 원하는 식물의 상세 관리 화면으로 이동할 수 있는 기능이다. 등록 식물이 없을 때는 사진 식별 또는 직접 등록으로 이어지는 안내를 제공한다. 이 기능은 식물 식별과 신규 등록 자체가 아니라 등록 후 관리 대상에 접근하는 경험을 다룬다.

- **동작**: - 시스템은 사용자의 등록 식물을 도감 목록으로 조회한다.
  - 사용자는 목록에서 식물을 선택해 해당 식물의 상세 화면으로 이동한다.
  - 등록 식물이 없으면 사용자는 사진 식별 또는 직접 등록을 시작할 수 있다.
- **결과**: - 등록 식물이 개인 도감 목록에 표시된다.
  - 선택한 식물의 관리 상세 정보 화면이 열린다.
  - 등록 식물이 없을 때 식물 등록을 유도하는 안내가 표시된다.

- **권한 & 접근**: - 사용자는 본인이 등록한 식물만 개인 도감에서 조회할 수 있다.
- **비즈니스 규칙**: - 식물 등록이 완료되면 해당 식물은 개인 도감 목록에 즉시 반영한다.
- **데이터**: - 식물 목록 항목은 식물 식별자, 사용자 식별자, 식물명, 대표 이미지 경로, 등록 시각을 포함한다.

```
1. ○ 식물별 물 주기 간격과 마지막 물 주기일을 기준으로 다음 예정일이 계산된다.
2. ○ 관리 예정일에 모바일 알림이 발송된다.
3. ○ 사용자가 알림에서 물 주기 완료를 기록할 수 있다.
4. ○ 완료 기록 후 다음 관리 예정일이 갱신된다.
5. ○ 사용자가 식물별 알림을 켜거나 끌 수 있다.
6. ○ 사용자가 기본 알림 시간과 알림 빈도를 설정할 수 있다.

### 3.1 식물별 물 주기 일정 계산
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

일반 사용자가 등록 식물의 권장 물 주기 간격과 마지막 물 주기일을 바탕으로 다음 물 주기 예정일을 확인할 수 있는 기능이다. 식물별로 독립적인 관리 일정을 계산하며, 날씨 기반 환경 주의나 다른 관리 유형의 일정 계산은 포함하지 않는다.

**개발 준비 슬롯**
- **선행조건**: - 사용자가 개인 도감에 식물을 등록한다.
  - 등록 식물에 권장 물 주기 간격과 마지막 물 주기일이 존재한다.
- **트리거**: - 식물이 등록되거나 마지막 물 주기일이 등록 또는 변경되면 다음 물 주기 예정일을 계산한다.
- **동작**: - 시스템은 식물별 물 주기 간격과 마지막 물 주기일을 기준으로 다음 물 주기 예정일을 계산한다.
  - 시스템은 계산된 예정일을 해당 식물의 관리 일정으로 저장한다.
- **결과**: - 사용자는 식물별 다음 물 주기 예정일을 확인할 수 있다.

### 3.2 물 주기 알림 발송 및 설정

- **데이터**: - 관리 지역 설정 데이터에는 사용자 식별자, 지역 설정 방식, 위치 사용 동의 상태, 관리 지역 정보, 설정 시각을 저장한다.


#### 4.1.2 직접 선택한 관리 지역 설정 및 변경

일반 사용자가 위치 권한 없이도 날씨 기반 관리에 사용할 지역을 직접 검색하거나 선택하고, 앱 설정에서 해당 지역을 변경하는 기능이다. 직접 설정한 지역은 현재 위치보다 우선하는 날씨 조회 기준으로 사용되며, 사용자는 언제든 다른 지역으로 변경할 수 있다. 위치 권한 요청과 날씨 위험 판단은 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 모바일 앱의 날씨 기반 관리 설정 또는 앱 설정 화면에 접근한다.
- **트리거**: - 사용자가 직접 지역 선택을 요청하거나 기존 관리 지역의 변경을 선택한다.
- **동작**: - 사용자는 관리에 사용할 지역을 검색하거나 목록에서 선택한다.
  - 사용자는 선택한 지역을 확인하고 관리 지역으로 저장한다.
  - 사용자는 필요할 때 저장된 관리 지역을 다른 지역으로 변경한다.
- **결과**: - 사용자가 선택한 지역이 날씨 기반 관리 안내의 조회 기준으로 저장된다.
  - 변경된 관리 지역은 이후 날씨 정보 조회와 환경 위험 판단에 반영된다.
- **예외**: - 지역 검색 결과가 없으면 검색어를 수정하거나 다시 선택하도록 안내한다.
  - 관리 지역 저장에 실패하면 기존 지역 설정을 유지하고 다시 시도 방법을 안내한다.
- **표시**: - 지역 설정 화면에는 지역 검색 입력란과 검색 결과 목록을 표시한다.
  - 설정 화면에는 현재 선택된 관리 지역과 지역 변경 버튼을 표시한다.
  - 저장 성공 또는 실패 결과를 사용자에게 표시한다.
- **권한 & 접근**: - 일반 사용자는 자신의 계정에 연결된 관리 지역만 설정하거나 변경할 수 있다.
  - 직접 지역 선택에는 기기 위치 권한이 필요하지 않다.
- **비즈니스 규칙**: - 사용자가 직접 선택한 지역은 위치 권한 없이 날씨 조회 기준으로 사용할 수 있다.
  - 사용자가 직접 선택한 관리 지역은 이후 날씨 기반 안내에서 현재 위치보다 우선하여 적용한다.
- **데이터**: - 관리 지역 데이터에는 사용자 식별자, 행정구역 또는 지역 식별자, 지역명, 설정 방식, 마지막 수정 시각을 저장한다.


#### 4.1.3 관리 지역 날씨 정보 조회 및 상태 표시

앱이 사용자가 설정한 관리 지역의 기온, 습도, 강수 정보를 날씨 API에서 조회하고 최신 조회 상태를 표시하는 기능이다. 조회한 날씨 정보는 식물별 환경 위험 판단의 입력값으로 제공되며, API 장애가 발생해도 기본 식물 관리 기능은 계속 이용할 수 있다. 위험 판단과 푸시 알림 발송은 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 현재 위치 또는 직접 선택 방식으로 관리 지역을 설정한다.
  - 날씨 API를 통해 관리 지역의 날씨 정보를 조회할 수 있다.
- **트리거**: - 사용자가 날씨 기반 관리 안내를 조회하거나 시스템의 날씨 정보 갱신 시점이 도래한다.
- **동작**: - 앱은 설정된 관리 지역을 기준으로 날씨 API에서 기온, 습도, 강수 정보를 조회한다.
  - 앱은 조회한 날씨 정보와 조회 시각 및 상태를 저장한다.
  - 앱은 저장된 날씨 정보를 식물별 환경 위험 판단 기능에 제공한다.
- **결과**: - 사용자는 설정된 관리 지역의 최신 날씨 정보와 마지막 조회 상태를 확인할 수 있다.
  - 시스템은 최신 날씨 정보를 환경 위험 판단의 입력값으로 사용할 수 있다.
- **예외**: - 날씨 API 오류 또는 데이터 지연이 발생하면 날씨 정보가 최신이 아닐 수 있음을 안내한다.
  - 날씨 정보 조회에 실패해도 사용자는 도감과 기본 관리 정보를 계속 이용할 수 있다.
  - 이전에 조회한 날씨 정보가 있으면 해당 정보의 조회 시각과 함께 최신 정보가 아님을 표시한다.
- **표시**: - 날씨 기반 관리 화면에는 현재 설정된 관리 지역을 표시한다.
  - 날씨 정보에는 기온, 습도, 강수 정보와 마지막 조회 시각을 표시한다.
  - 조회 실패 또는 데이터 지연 시에는 상태와 다시 시도 가능 여부를 표시한다.
- **권한 & 접근**: - 일반 사용자는 자신의 관리 지역에 연결된 날씨 정보만 조회할 수 있다.
- **비즈니스 규칙**: - 날씨 정보 조회 실패는 식물 도감과 기본 관리 기능의 이용을 차단하지 않는다.
  - 날씨 정보는 설정된 관리 지역을 기준으로 조회한다.
  - 날씨 정보의 최신성 상태를 환경 위험 판단과 사용자 화면에 함께 반영한다.
- **데이터**: - 날씨 데이터에는 관리 지역 식별자, 기온, 습도, 강수 정보, 데이터 기준 시각, 조회 시각, 조회 상태를 저장한다.
  - 날씨 조회 이력에는 사용자 식별자, 관리 지역 식별자, 조회 요청 시각, 성공 또는 실패 상태를 기록한다.


### 4.2 식물별 환경 위험 판단 및 행동 안내
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자, 콘텐츠 관리자 | **기기**: 모바일 앱, 웹 관리자 화면

앱이 등록 식물의 적정 온도·습도 정보와 관리 지역의 현재 날씨를 비교하여 고온·저온·건조·과습 위험을 판단하는 기능이다. 위험이 감지되면 일반 사용자는 식물별로 이해하기 쉬운 주의 이유와 환기·위치 이동·분무 같은 실행 가능한 행동을 확인한다. 전문적인 생육 진단이나 사용자의 조치 이행을 자동 검증하는 범위는 포함하지 않는다.

**개발 준비 슬롯**
- **선행조건**: - 식물에는 적정 온도와 적정 습도 정보가 등록되어 있다.
  - 관리 지역의 최신 날씨 정보를 조회할 수 있다.
- **트리거**: - 현재 날씨가 식물의 적정 온도 또는 습도 범위를 벗어나 위험 조건을 충족한다.
- **동작**: - 앱은 식물별 적정 환경과 현재 기온, 습도, 강수 정보를 비교한다.
  - 앱은 고온, 저온, 건조, 과습 가능성을 식물별로 판단한다.
  - 콘텐츠 관리자는 위험 유형별 초보자용 관리 행동 문구를 관리한다.
- **결과**: - 사용자는 위험이 발생한 식물, 위험 유형, 주의 이유와 권장 관리 행동을 확인한다.
  - 안내에는 환기, 위치 이동, 분무 등 사용자가 바로 실행할 수 있는 행동을 포함한다.
- **예외**: - 식물의 적정 환경 정보가 없으면 앱은 날씨 기반 위험 판단을 제공할 수 없음을 안내한다.
  - 날씨 데이터가 오래되었거나 조회에 실패하면 앱은 위험 판단 결과의 최신 상태를 안내한다.
- **표시**: - 앱은 식물 이름과 함께 고온, 저온, 건조, 과습 중 해당 위험 유형을 명확히 표시한다.
  - 앱은 전문 용어 대신 짧고 행동 중심의 문장으로 권장 조치를 제공한다.
- **권한 & 접근**: - 일반 사용자는 본인이 등록한 식물의 환경 안내를 조회할 수 있다.
  - 콘텐츠 관리자는 식물 환경 정보와 위험별 안내 콘텐츠를 관리할 수 있다.
- **비즈니스 규칙**: - 위험 판단은 식물별 적정 온도·습도와 현재 환경 정보를 함께 기준으로 한다.
  - 날씨 기반 안내는 식물의 상태를 확정 진단하는 정보가 아니라 관리 주의 정보로 제공한다.
- **데이터**: - 식물 환경 정보에는 적정 온도 범위와 적정 습도 범위를 포함한다.
  - 위험 안내 기록에는 대상 식물, 위험 유형, 판단 시각, 비교한 날씨 값, 권장 행동을 포함한다.


#### 4.2.1 식물별 환경 위험 판단

- **결과**: - 사용자는 위험이 발생한 식물과 해당 위험 유형을 확인할 수 있다.

#### 4.2.2 환경 위험별 관리 행동 안내

일반 사용자가 식물별 환경 위험 결과에서 위험의 이유와 초보자용 권장 관리 행동을 확인하는 기능이다. 안내는 환기, 위치 이동, 분무 등 즉시 실행 가능한 행동 중심으로 제공하며, 사용자의 조치 이행을 자동으로 검증하거나 알림을 발송하는 범위는 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자, 콘텐츠 관리자 | **기기**: 모바일 앱, 웹 관리자 화면

**개발 준비 슬롯**
- **선행조건**: - 대상 식물에서 날씨 기반 환경 위험이 판단되어 있다.
  - 위험 유형에 연결된 사용자용 관리 행동 안내 콘텐츠가 공개 상태로 제공된다.
- **트리거**: - 사용자가 식물별 환경 위험 안내를 선택한다.
  - 사용자가 날씨 기반 위험 알림에서 상세 안내 화면으로 이동한다.
- **동작**: - 앱은 대상 식물의 위험 유형과 현재 환경이 주의가 필요한 이유를 표시한다.
  - 앱은 위험 유형에 맞는 권장 관리 행동을 사용자에게 제공한다.
  - 콘텐츠 관리자는 웹 관리자 화면에서 위험 유형별 초보자용 관리 행동 문구를 등록하거나 수정한다.
- **결과**: - 사용자는 위험이 발생한 식물에 대해 바로 수행할 수 있는 관리 행동을 이해할 수 있다.
  - 시스템은 환경 위험 안내 조회 이벤트를 기록한다.
- **예외**: - 위험 판단 결과는 있지만 연결된 관리 행동 콘텐츠가 없으면 위험 유형과 기본 주의 안내를 표시한다.
  - 관리 행동 안내 콘텐츠를 불러오지 못하면 오류 상태를 표시하고 다시 시도할 수 있게 한다.
- **표시**: - 안내 화면에는 식물명, 위험 유형, 주의 이유, 권장 관리 행동을 함께 표시한다.
  - 권장 관리 행동은 전문 용어를 줄이고 짧고 행동 중심의 문장으로 표시한다.
  - 여러 위험이 있는 경우 각 위험의 권장 행동을 구분해 표시한다.
- **권한 & 접근**: - 일반 사용자는 본인이 등록한 식물의 환경 위험 행동 안내를 조회할 수 있다.
  - 콘텐츠 관리자는 위험 유형별 관리 행동 안내 콘텐츠를 등록하거나 수정할 수 있다.
- **비즈니스 규칙**: - 권장 관리 행동은 환기, 위치 이동, 분무 등 사용자가 즉시 수행할 수 있는 내용으로 제공한다.
  - 안내 콘텐츠는 식물의 질병이나 생육 상태를 확정 진단하는 표현을 사용하지 않는다.
  - 사용자용 안내에는 공개 상태의 최신 콘텐츠만 반영한다.
- **데이터**: - 위험 행동 안내 콘텐츠에는 위험 유형, 사용자용 주의 이유, 권장 행동, 게시 상태, 수정 시각을 저장한다.
  - 위험 안내 조회 기록에는 사용자 식별자, 대상 식물 식별자, 위험 유형, 조회 시각을 저장한다.


### 4.3 날씨 기반 관리 주의 알림 설정 및 발송
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

일반 사용자가 날씨 기반 관리 주의 알림을 전체 또는 식물별로 켜고 끌 수 있으며, 위험 조건 발생 시 모바일 알림으로 안내를 받는 기능이다. 알림을 선택한 사용자는 앱에서 위험 내용과 권장 행동을 이어서 확인할 수 있다. 물 주기 예정일 계산과 물 주기 완료 기록은 별도의 관리 알림 기능 범위로 제외한다.

**개발 준비 슬롯**
- **선행조건**: - 사용자는 모바일 알림 권한을 허용했다.
  - 사용자는 날씨 기반 알림을 전체 또는 대상 식물에 대해 활성화했다.
  - 대상 식물에서 날씨 기반 위험이 판단되었다.
- **트리거**: - 날씨 기반 위험 판단 결과가 알림 발송 조건을 충족한다.
- **동작**: - 사용자는 날씨 기반 알림을 전체적으로 켜거나 끈다.
  - 사용자는 식물별로 날씨 기반 알림을 켜거나 끈다.
  - 앱은 활성화된 알림 설정에 따라 위험 안내를 모바일 알림으로 발송한다.
- **결과**: - 사용자는 알림에서 대상 식물의 위험 유형과 권장 관리 행동을 확인한다.
  - 사용자는 알림을 선택해 앱의 상세 관리 안내로 이동할 수 있다.
- **예외**: - 모바일 알림 권한이 없으면 앱은 권한 설정 방법과 앱 내 확인 경로를 안내한다.
  - 알림 발송에 실패해도 위험 안내는 앱 내에서 조회할 수 있다.
- **표시**: - 알림에는 대상 식물명, 위험 유형, 즉시 확인할 수 있는 짧은 관리 행동을 표시한다.
  - 설정 화면에는 전체 알림 상태와 식물별 알림 상태를 구분해 표시한다.
- **권한 & 접근**: - 앱은 사용자의 운영체제 알림 권한이 허용된 경우에만 푸시 알림을 발송한다.
- **비즈니스 규칙**: - 전체 날씨 기반 알림이 비활성화되면 식물별 활성화 상태와 관계없이 날씨 기반 푸시 알림을 발송하지 않는다.
  - 식물별 알림이 비활성화되면 해당 식물의 날씨 기반 푸시 알림을 발송하지 않는다.
- **데이터**: - 알림 설정에는 전체 날씨 기반 알림 상태와 식물별 알림 상태를 저장한다.
  - 알림 발송 기록에는 대상 식물, 위험 유형, 발송 시각, 발송 상태를 저장한다.


#### 4.3.1 전체 및 식물별 날씨 알림 설정 관리

일반 사용자가 모바일 앱 설정에서 날씨 기반 관리 주의 알림을 전체적으로 켜거나 끄고, 등록 식물별 수신 여부를 개별 설정하는 기능이다. 전체 설정과 식물별 설정의 우선순위를 일관되게 적용하여 사용자가 원하지 않는 식물의 날씨 알림을 받지 않도록 한다. 날씨 위험 판단과 관리 행동 콘텐츠 생성은 이 기능 범위에 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 모바일 앱에 로그인하고 하나 이상의 식물을 등록한다.
  - 날씨 기반 관리 안내 기능을 이용할 수 있는 상태이다.
- **트리거**: - 사용자가 앱 설정 또는 식물별 관리 화면에서 날씨 기반 알림 설정을 선택한다.
- **동작**: - 사용자는 전체 날씨 기반 알림을 켜거나 끈다.
  - 사용자는 등록 식물별 날씨 기반 알림을 켜거나 끈다.
  - 시스템은 사용자가 변경한 알림 설정을 저장한다.
- **결과**: - 사용자가 전체 알림 상태와 식물별 알림 상태를 확인할 수 있다.
  - 저장된 설정은 이후 날씨 위험 알림 발송 여부에 반영된다.
- **예외**: - 알림 설정 저장에 실패하면 기존 설정을 유지하고 실패 사실 및 재시도 방법을 안내한다.
  - 등록 식물이 없으면 식물별 설정 목록 대신 식물 등록을 안내한다.
- **표시**: - 설정 화면에는 전체 날씨 기반 알림의 활성 상태를 표시한다.
  - 식물별 설정 목록에는 식물명과 각 식물의 알림 활성 상태를 표시한다.
  - 전체 알림을 끄면 식물별 설정과 관계없이 푸시 알림이 발송되지 않음을 안내한다.
- **권한 & 접근**: - 사용자는 자신의 계정에 등록된 식물의 날씨 기반 알림 설정만 변경할 수 있다.
- **비즈니스 규칙**: - 전체 날씨 기반 알림이 비활성화되면 식물별 활성화 상태와 관계없이 날씨 기반 푸시 알림을 발송하지 않는다.
  - 전체 날씨 기반 알림이 활성화된 경우에만 식물별 알림 활성 상태를 발송 조건으로 적용한다.
  - 식물별 알림 설정은 사용자가 명시적으로 변경하기 전까지 유지한다.
- **데이터**: - 날씨 기반 알림 설정 데이터에는 사용자 식별자, 전체 알림 활성 상태, 식물 식별자, 식물별 알림 활성 상태, 수정 시각을 저장한다.


#### 4.3.2 날씨 위험 푸시 알림 발송 및 상세 안내 연결

앱은 날씨 기반 위험 판단 결과가 있고 사용자의 알림 설정 및 운영체제 권한이 충족되면 대상 식물의 위험 유형과 권장 행동을 모바일 푸시 알림으로 발송한다. 일반 사용자는 알림을 선택하여 앱의 해당 식물 관리 안내로 이동하고 위험 내용과 상세 행동을 확인한다. 위험 판단 로직 자체와 알림 수신 후 관리 완료 기록은 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 대상 식물에서 날씨 기반 환경 위험이 판단된다.
  - 사용자가 전체 및 대상 식물의 날씨 기반 알림을 활성화한다.
  - 사용자가 운영체제 알림 권한을 허용한다.
- **트리거**: - 날씨 기반 위험 판단 결과가 알림 발송 조건을 충족한다.
- **동작**: - 시스템은 대상 식물명, 위험 유형, 짧은 권장 관리 행동을 포함한 모바일 푸시 알림을 생성한다.
  - 시스템은 사용자의 전체 및 식물별 알림 설정을 확인한 뒤 알림을 발송한다.
  - 사용자가 알림을 선택하면 앱은 대상 식물의 날씨 기반 관리 상세 안내를 표시한다.
- **결과**: - 사용자는 알림에서 위험이 발생한 식물과 즉시 수행할 관리 행동을 확인할 수 있다.
  - 사용자는 알림을 통해 대상 식물의 위험 유형, 주의 이유, 권장 행동이 포함된 상세 안내로 이동할 수 있다.
  - 시스템은 알림 발송 결과와 알림 선택 이벤트를 기록한다.
- **예외**: - 운영체제 알림 권한이 없으면 앱은 권한 활성화 방법과 앱 내 위험 안내 확인 경로를 안내한다.
  - 푸시 알림 발송에 실패해도 위험 안내는 앱 내에서 조회할 수 있다.
  - 대상 식물의 위험 안내 상세 정보를 불러오지 못하면 오류를 안내하고 다시 시도할 수 있게 한다.
- **표시**: - 푸시 알림에는 대상 식물명, 위험 유형, 짧고 행동 중심의 권장 조치를 표시한다.
  - 앱의 상세 안내 화면에는 위험 유형, 판단 시각, 주의 이유, 권장 관리 행동을 표시한다.
  - 알림 권한이 비활성화된 경우 설정 화면에는 권한 상태와 활성화 안내를 표시한다.
- **권한 & 접근**: - 앱은 사용자의 운영체제 알림 권한이 허용된 경우에만 푸시 알림을 발송한다.
  - 사용자는 자신의 등록 식물에 대한 날씨 위험 알림과 상세 안내만 조회할 수 있다.
- **비즈니스 규칙**: - 전체 날씨 기반 알림 또는 대상 식물의 알림이 비활성화된 경우 푸시 알림을 발송하지 않는다.
  - 알림 내용은 식물 상태의 확정 진단이 아니라 날씨 기반 관리 주의 안내임을 전제로 한다.
- **데이터**: - 날씨 위험 알림 발송 기록에는 사용자 식별자, 대상 식물 식별자, 위험 유형, 권장 행동, 판단 시각, 발송 시각, 발송 상태를 저장한다.
  - 알림 상호작용 기록에는 알림 식별자, 선택 시각, 상세 안내 이동 여부를 저장한다.

## 5. 미니홈피 및 식물 미니어처 꾸미기
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중

사용자가 등록한 식물을 미니어처 형태로 미니홈피에 배치하고 배경, 가구, 장식 아이템 등을 활용해 공간을 꾸밀 수 있도록 한다. 꾸미기 기능은 식물 관리의 보조적인 즐거움으로 제공하며, 기본 관리 기능을 이용하지 않아도 사용할 수 있도록 선택 기능으로 운영한다.

**수용 기준:**
```
1. ○ 등록한 식물이 미니어처 형태로 미니홈피에 추가될 수 있다.
2. ○ 사용자가 미니어처의 위치와 배치를 변경할 수 있다.
3. ○ 사용자가 보유한 배경 및 장식 아이템을 미니홈피에 적용할 수 있다.
4. ○ 미니홈피의 변경 사항이 저장되고 다음 접속 시 유지된다.
5. ○ 꾸미기 기능을 사용하지 않아도 식물 식별과 관리 알림 기능을 정상적으로 이용할 수 있다.
6. ○ 사용자가 완성한 미니홈피를 이미지 또는 공유 링크 형태로 선택적으로 공유할 수 있다.
```


### 5.1 등록 식물 미니어처 생성 및 배치
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

일반 사용자가 개인 도감에 등록한 식물을 미니홈피용 미니어처로 확인하고 공간에 추가·배치할 수 있는 기능이다. 등록 식물과 미니어처의 연결 및 기본 배치 경험을 포함하며, 배경·가구 등 꾸미기 아이템의 획득과 관리 기능은 포함하지 않는다.

**개발 준비 슬롯**

## 6. 꾸미기 아이템 창고 및 상점
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 작성중

사용자가 보유한 꾸미기 아이템을 창고에서 확인하고, 상점에서 신규 아이템을 획득할 수 있도록 한다. 상점은 초기에는 무료 또는 서비스 내 재화 기반으로 운영할 수 있으며, 아이템 보유 상태와 사용 상태를 명확히 구분한다.

**수용 기준:**
```
1. ○ 사용자가 보유한 꾸미기 아이템을 종류별로 조회할 수 있다.
2. ○ 상점에서 아이템의 이미지, 이름, 설명, 획득 조건을 확인할 수 있다.
3. ○ 사용자가 획득한 아이템은 창고에 자동으로 반영된다.
4. ○ 이미 보유한 아이템을 중복 획득할 때의 처리 방식이 안내된다.
5. ○ 아이템을 미니홈피에 적용하거나 해제할 수 있다.
6. ○ 상점 및 창고 기능 장애가 발생해도 식물 등록, 도감, 관리 알림은 정상적으로 이용할 수 있다.
```


### 6.1 꾸미기 아이템 창고 조회 및 보유 상태 관리

**개발 준비 슬롯**
- **선행조건**: - 사용자가 앱에 로그인되어 있다.

- **동작**: - 시스템은 사용자의 보유 아이템을 종류별로 조회할 수 있게 한다.

### 6.2 꾸미기 아이템 상점 탐색 및 획득

  - 사용자 아이템 보유 데이터는 사용자 식별자, 아이템 식별자, 획득 일시, 보유 상태를 포함한다.


#### 6.2.1 상점 아이템 목록 및 상세 정보 확인

일반 사용자가 모바일 앱의 꾸미기 아이템 상점에서 획득 가능한 아이템을 목록과 상세 정보로 확인하는 기능이다. 사용자는 아이템의 이미지, 이름, 설명, 획득 조건 및 본인 보유 여부를 비교해 획득할 아이템을 결정한다. 아이템 획득 처리와 창고 반영은 이 기능에 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 모바일 앱에 로그인한다.
  - 상점에 노출 가능한 꾸미기 아이템과 획득 조건이 등록되어 있다.
- **트리거**: - 사용자가 미니홈피 또는 창고 화면에서 상점 진입을 선택한다.
  - 사용자가 상점 목록에서 특정 아이템을 선택한다.
- **동작**: - 시스템은 상점에서 획득 가능한 아이템 목록을 표시한다.
  - 시스템은 각 아이템의 이미지, 이름, 설명, 획득 조건 및 사용자 보유 여부를 표시한다.
  - 사용자는 특정 아이템을 선택하여 상세 정보와 획득 경로를 확인한다.
- **결과**: - 사용자는 획득할 수 있는 꾸미기 아이템과 각 아이템의 획득 조건을 확인할 수 있다.
  - 사용자는 선택한 아이템의 획득 처리 화면으로 이동할 수 있다.
- **예외**: - 상점 아이템 정보를 불러오지 못하면 오류 상태와 다시 시도 방법을 안내한다.
  - 현재 노출 가능한 아이템이 없으면 빈 상점 상태를 안내한다.
- **표시**: - 상점 목록의 각 아이템에는 이미지, 이름, 간단한 설명, 획득 조건 및 보유 여부를 표시한다.
  - 아이템 상세 화면에는 획득에 필요한 조건과 획득 시작 버튼을 표시한다.
  - 이미 보유한 아이템은 보유 중 상태로 구분해 표시한다.
- **권한 & 접근**: - 일반 사용자는 상점에 공개된 아이템 정보를 조회할 수 있다.
- **비즈니스 규칙**: - 노출 상태인 아이템만 일반 사용자 상점 목록과 상세 화면에 표시한다.
  - 아이템 보유 여부는 로그인한 사용자의 창고 데이터를 기준으로 표시한다.
- **데이터**: - 상점 아이템 정보에는 아이템 식별자, 이름, 종류, 이미지, 설명, 획득 조건, 노출 상태를 저장한다.
  - 상점 조회 정보에는 사용자 식별자, 조회한 아이템 식별자, 조회 시각을 기록한다.


#### 6.2.2 상점 아이템 획득 처리 및 창고 반영

일반 사용자가 상점에서 선택한 꾸미기 아이템의 획득 조건을 충족한 뒤 아이템을 획득하고 결과를 확인하는 기능이다. 획득에 성공한 아이템은 사용자 창고에 자동 반영되며, 이미 보유한 아이템을 다시 획득하려는 경우에는 정해진 중복 처리 정책을 안내한다. 창고 목록 조회와 미니홈피 적용·해제는 이 기능에 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 모바일 앱에 로그인한다.
  - 사용자가 상점에서 획득할 아이템을 선택한다.
  - 선택한 아이템이 상점에 노출 중이며 획득 조건이 등록되어 있다.
- **트리거**: - 사용자가 아이템 상세 화면에서 획득을 선택한다.
- **동작**: - 시스템은 선택한 아이템의 노출 상태, 사용자 보유 여부 및 획득 조건을 확인한다.
  - 시스템은 사용자가 획득 조건을 충족한 경우 아이템 획득을 처리한다.
  - 시스템은 획득 성공한 아이템을 사용자 창고에 보유 상태로 자동 반영한다.
  - 시스템은 획득 성공, 조건 미충족, 중복 획득 또는 처리 실패 결과를 사용자에게 안내한다.
- **결과**: - 사용자는 아이템 획득 성공 여부와 처리 결과를 확인할 수 있다.
  - 새로 획득한 아이템은 사용자 창고에서 보유 상태로 조회할 수 있다.
- **예외**: - 사용자가 획득 조건을 충족하지 못하면 부족한 조건과 충족 방법을 안내한다.
  - 아이템 획득 처리 또는 창고 반영에 실패하면 실패 사실과 다시 시도 방법을 안내한다.
  - 이미 보유한 아이템을 다시 획득하려 하면 중복 획득 처리 정책에 따른 결과를 안내한다.
- **표시**: - 획득 확인 화면에는 선택한 아이템의 이미지, 이름 및 획득 조건을 표시한다.
  - 획득 완료 화면에는 새로 보유하게 된 아이템과 창고로 이동하는 버튼을 표시한다.
  - 획득 실패 또는 중복 획득 상황에서는 처리 사유와 다음 행동을 표시한다.
- **권한 & 접근**: - 일반 사용자는 자신의 계정으로만 상점 아이템을 획득할 수 있다.
  - 콘텐츠 관리자는 웹 관리자 화면에서 상점 아이템 정보와 획득 조건을 관리할 수 있다.
- **비즈니스 규칙**: - 아이템 획득은 사용자가 획득을 명시적으로 선택하고 해당 조건을 충족한 경우에만 완료한다.
  - 획득이 완료된 아이템은 사용자 창고에 자동으로 반영한다.
  - 상점 또는 창고 기능에 장애가 발생해도 식물 등록, 도감, 관리 알림 기능은 계속 이용할 수 있어야 한다.
- **데이터**: - 아이템 획득 기록에는 사용자 식별자, 아이템 식별자, 획득 시각, 획득 상태, 처리 결과 및 실패 사유를 저장한다.
  - 사용자 아이템 보유 데이터에는 사용자 식별자, 아이템 식별자, 보유 상태, 획득 일시를 저장한다.
  - 중복 획득 처리 기록에는 사용자 식별자, 아이템 식별자, 처리 정책 및 처리 결과를 저장한다.


### 6.3 창고 아이템의 미니홈피 적용 및 해제
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

일반 사용자가 창고에 보유한 꾸미기 아이템을 자신의 미니홈피에 적용하거나 적용을 해제하는 기능이다. 적용 상태를 창고와 미니홈피에 일관되게 반영하여 사용자가 현재 사용 중인 아이템을 알 수 있게 한다. 미니홈피 내 아이템의 좌표 이동과 공간 배치 편집은 미니홈피 꾸미기 기능에서 다룬다.

**개발 준비 슬롯**
- **선행조건**: - 사용자가 앱에 로그인되어 있다.
  - 사용자가 적용하려는 꾸미기 아이템을 창고에 보유하고 있다.
- **트리거**: - 사용자가 창고 또는 미니홈피 꾸미기 화면에서 보유 아이템의 적용 또는 해제를 선택한다.
- **동작**: - 시스템은 사용자가 보유한 아이템만 미니홈피에 적용할 수 있게 한다.
  - 시스템은 사용자가 적용 중인 아이템을 해제할 수 있게 한다.
  - 시스템은 적용 또는 해제 결과를 창고와 미니홈피에 반영한다.
- **결과**: - 적용한 아이템은 미니홈피에 표시되고 창고에서 적용 중 상태로 표시된다.
  - 해제한 아이템은 미니홈피에서 제거되고 창고에서는 보유 상태를 유지한다.
- **예외**: - 보유하지 않은 아이템의 적용 요청은 차단하고 획득 경로를 안내한다.
  - 적용 상태 저장에 실패하면 기존 적용 상태를 유지하고 다시 시도 방법을 안내한다.
- **표시**: - 창고와 미니홈피 꾸미기 화면에서 각 아이템의 적용 가능 여부와 적용 상태를 표시한다.
  - 적용 및 해제 후 변경 결과를 즉시 확인할 수 있게 한다.
- **권한 & 접근**: - 일반 사용자는 자신의 보유 아이템을 자신의 미니홈피에만 적용하거나 해제할 수 있다.
- **비즈니스 규칙**: - 아이템을 해제해도 사용자의 창고 보유 기록은 삭제하지 않는다.
  - 적용 상태 변경은 저장되어 다음 접속 시에도 유지한다.
- **데이터**: - 미니홈피 적용 데이터는 사용자 식별자, 아이템 식별자, 적용 상태, 적용 일시를 포함한다.


#### 6.3.1 보유 아이템 미니홈피 적용

일반 사용자가 창고 또는 미니홈피 꾸미기 화면에서 보유한 꾸미기 아이템을 선택하여 자신의 미니홈피에 적용하는 기능이다. 적용 성공 시 아이템은 미니홈피 구성에 표시되고 창고에서는 적용 중 상태로 갱신된다. 아이템 획득, 창고 목록 조회, 공간 내 세부 좌표 이동은 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 모바일 앱에 로그인한다.
  - 사용자가 적용하려는 꾸미기 아이템을 창고에 보유한다.
  - 사용자가 자신의 미니홈피에 접근할 수 있다.
- **트리거**: - 사용자가 창고 또는 미니홈피 꾸미기 화면에서 보유 아이템의 적용을 선택한다.
- **동작**: - 시스템은 사용자가 선택한 아이템의 보유 상태와 적용 가능 여부를 확인한다.
  - 시스템은 적용 가능한 보유 아이템을 사용자의 미니홈피 구성에 추가하거나 배경으로 설정한다.
  - 시스템은 아이템의 적용 상태를 저장하고 창고 정보에 반영한다.
- **결과**: - 적용한 아이템이 사용자의 미니홈피에 표시된다.
  - 적용한 아이템은 창고에서 보유 중 및 적용 중 상태로 구분되어 표시된다.
  - 저장된 적용 상태는 다음 접속 시에도 유지된다.
- **예외**: - 사용자가 보유하지 않은 아이템의 적용을 요청하면 적용을 차단하고 획득 경로를 안내한다.

  - 적용하려는 아이템이 현재 공간 구성 규칙과 충돌하면 적용할 수 없는 이유를 안내한다.
- **표시**: - 아이템 목록에는 각 보유 아이템의 적용 가능 여부와 현재 적용 상태를 표시한다.
  - 아이템 적용 후 미니홈피에서 변경된 결과를 즉시 표시한다.
  - 적용 성공 또는 실패 결과를 사용자에게 명확히 표시한다.
- **권한 & 접근**: - 사용자는 자신의 창고에 보유한 아이템만 자신의 미니홈피에 적용할 수 있다.
- **비즈니스 규칙**: - 보유하지 않은 아이템은 미니홈피에 적용할 수 없다.
  - 아이템 적용 상태는 창고의 보유 상태와 별도로 관리한다.
  - 배경은 한 번에 하나만 적용하며, 가구와 장식의 동시 적용 개수는 미니홈피 구성 규칙을 따른다.
- **데이터**: - 미니홈피 아이템 적용 데이터에는 사용자 식별자, 미니홈피 식별자, 아이템 식별자, 적용 상태, 적용 시각을 저장한다.
  - 아이템 상태 데이터에는 사용자 식별자, 아이템 식별자, 보유 상태와 적용 상태를 저장한다.


#### 6.3.2 적용 아이템 미니홈피 해제

일반 사용자가 자신의 미니홈피에 적용 중인 꾸미기 아이템을 해제하여 공간에서 제거하는 기능이다. 해제한 아이템의 창고 보유 기록은 유지되고 적용 상태만 해제됨으로 변경된다. 아이템 삭제, 재획득, 다른 아이템의 위치 편집은 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 모바일 앱에 로그인한다.
  - 사용자의 미니홈피에 해제할 적용 중 꾸미기 아이템이 존재한다.
- **트리거**: - 사용자가 창고 또는 미니홈피 꾸미기 화면에서 적용 중인 아이템의 해제를 선택한다.
- **동작**: - 시스템은 사용자가 선택한 아이템이 자신의 미니홈피에 적용 중인지 확인한다.
  - 시스템은 해당 아이템을 미니홈피 구성에서 제거한다.
  - 시스템은 아이템 적용 상태를 해제로 변경하고 변경 결과를 저장한다.
- **결과**: - 해제한 아이템은 미니홈피에서 더 이상 표시되지 않는다.
  - 해제한 아이템은 창고에서 보유 중 상태로 유지되고 적용 중 표시는 제거된다.
  - 저장된 해제 상태는 다음 접속 시에도 유지된다.
- **예외**: - 이미 해제되었거나 적용 상태를 조회할 수 없는 아이템은 해제할 수 없음을 안내한다.

  - 게시 상태 변경 결과를 콘텐츠 관리자에게 표시한다.
- **권한 & 접근**: - 콘텐츠 관리자만 콘텐츠의 게시 상태를 변경할 수 있다.
- **비즈니스 규칙**: - 사용자 도감과 관리 알림에는 공개 상태인 최신 관리 정보만 사용한다.
- **데이터**: - 식물 관리 콘텐츠는 공개 또는 비공개 게시 상태를 가진다.


#### 7.2.1 관리 콘텐츠 공개 게시

콘텐츠 관리자가 웹 관리자 화면에서 검토한 식물 관리 콘텐츠를 공개 상태로 전환하는 기능이다. 공개된 최신 콘텐츠는 일반 사용자의 도감 상세 화면과 관리 알림 기준에서 사용할 수 있으며, 콘텐츠 작성·수정 자체는 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 콘텐츠 관리자 | **기기**: 웹 관리자 화면

**개발 준비 슬롯**
- **선행조건**: - 콘텐츠 관리자가 게시할 식물 관리 콘텐츠를 생성하거나 수정한 상태이다.
  - 콘텐츠 관리자가 웹 관리자 화면에 로그인한다.
- **트리거**: - 콘텐츠 관리자가 콘텐츠 상세 화면에서 공개를 선택한다.
- **동작**: - 시스템은 콘텐츠 관리자의 공개 요청을 처리한다.
  - 시스템은 해당 콘텐츠의 게시 상태를 공개로 변경한다.
  - 시스템은 공개된 최신 콘텐츠를 사용자 도감 상세와 관리 알림 기준에 반영한다.
- **결과**: - 공개 상태의 최신 식물 관리 콘텐츠가 일반 사용자에게 제공된다.
  - 콘텐츠 관리자는 변경된 공개 상태를 확인할 수 있다.
- **예외**: - 게시 상태 변경 저장에 실패하면 기존 게시 상태를 유지하고 실패 사실 및 재시도 방법을 안내한다.
  - 필수 관리 정보가 누락된 콘텐츠는 공개를 진행하지 않고 보완이 필요한 항목을 안내한다.
- **표시**: - 콘텐츠 상세 화면에는 현재 게시 상태와 공개 실행 버튼을 표시한다.
  - 공개 완료 후에는 공개 상태, 반영 시각 및 처리 결과를 표시한다.
- **권한 & 접근**: - 콘텐츠 관리자만 식물 관리 콘텐츠를 공개 상태로 변경할 수 있다.
- **비즈니스 규칙**: - 사용자 도감 상세와 관리 알림에는 공개 상태인 최신 관리 콘텐츠만 사용한다.
  - 공개 처리 전의 비공개 콘텐츠는 일반 사용자에게 노출하지 않는다.
- **데이터**: - 콘텐츠 게시 데이터에는 콘텐츠 식별자, 게시 상태, 공개 처리 시각 및 처리한 콘텐츠 관리자 식별자를 저장한다.


#### 7.2.2 관리 콘텐츠 비공개 전환 및 사용자 노출 중단

콘텐츠 관리자가 오류 수정 또는 검수 미완료 등의 사유로 공개된 식물 관리 콘텐츠를 비공개 상태로 전환하는 기능이다. 비공개 전환 후 해당 콘텐츠는 일반 사용자 화면과 관리 알림 기준에서 제외되며, 콘텐츠 삭제와 편집 기능은 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 콘텐츠 관리자 | **기기**: 웹 관리자 화면

**개발 준비 슬롯**
- **선행조건**: - 콘텐츠 관리자가 비공개로 전환할 식물 관리 콘텐츠를 조회할 수 있다.
  - 대상 콘텐츠가 공개 상태이거나 게시 상태를 변경할 수 있는 상태이다.
- **트리거**: - 콘텐츠 관리자가 콘텐츠 상세 화면에서 비공개 전환을 선택하고 확인한다.
- **동작**: - 시스템은 콘텐츠의 게시 상태를 비공개로 변경한다.
  - 시스템은 비공개 전환된 콘텐츠를 사용자 도감 상세와 관리 알림 기준에서 제외한다.
  - 시스템은 비공개 전환 결과를 콘텐츠 관리자에게 표시한다.
- **결과**: - 일반 사용자는 비공개 상태가 된 관리 콘텐츠를 더 이상 조회할 수 없다.
  - 이후 생성되는 관리 알림은 비공개 전환된 콘텐츠의 기준을 사용하지 않는다.
- **예외**: - 게시 상태 변경 저장에 실패하면 기존 공개 상태를 유지하고 실패 사실 및 재시도 방법을 안내한다.
  - 비공개 전환 뒤 사용자용 대체 콘텐츠가 없으면 해당 관리 정보가 제공되지 않을 수 있음을 안내한다.
- **표시**: - 콘텐츠 목록과 상세 화면에는 현재 비공개 상태를 명확히 표시한다.
  - 비공개 전환 확인 화면에는 사용자 도감 및 관리 알림에 더 이상 반영되지 않음을 안내한다.
- **권한 & 접근**: - 콘텐츠 관리자만 식물 관리 콘텐츠를 비공개 상태로 변경할 수 있다.
- **비즈니스 규칙**: - 비공개 상태인 콘텐츠는 일반 사용자 화면과 관리 알림 기준에서 제외한다.
  - 비공개 전환은 콘텐츠 데이터를 삭제하지 않으며 콘텐츠 관리자는 이후 수정하거나 다시 공개할 수 있다.
- **데이터**: - 콘텐츠 게시 데이터에는 콘텐츠 식별자, 게시 상태, 비공개 처리 시각 및 처리한 콘텐츠 관리자 식별자를 저장한다.
  - 게시 상태 변경 기록은 변경 전 상태와 변경 후 상태를 포함한다.


### 7.3 관리 콘텐츠 변경 이력 조회
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 운영 관리자 | **기기**: 웹 관리자 화면

**기능의 근거**: 관리 정보의 변경 경위를 확인할 수 있어야 사용자에게 제공되는 정보의 정확성과 최신성을 운영 측면에서 검수할 수 있다.

운영 관리자는 식물 관리 콘텐츠의 변경 이력에서 변경 일시와 변경한 관리자를 확인한다. 이 기능은 콘텐츠의 정확성 검수와 운영 추적을 지원하며, 콘텐츠 자체를 수정하는 기능은 포함하지 않는다.

**개발 준비 슬롯**
- **선행조건**: - 변경 이력을 조회할 식물 관리 콘텐츠가 존재한다.
- **트리거**: - 운영 관리자가 콘텐츠 상세 화면에서 변경 이력 조회를 요청한다.
- **동작**: - 시스템이 해당 콘텐츠의 변경 이력을 시간순으로 조회하여 제공한다.
- **결과**: - 운영 관리자가 각 변경의 변경 일시와 변경한 관리자를 확인할 수 있다.
- **예외**: - 변경 이력이 없으면 이력이 없음을 표시한다.
- **표시**: - 변경 이력 목록에 변경 일시와 변경한 관리자를 표시한다.
- **권한 & 접근**: - 운영 관리자만 콘텐츠 변경 이력을 조회할 수 있다.
- **데이터**: - 변경 이력은 대상 콘텐츠, 변경 일시, 변경한 관리자 정보를 기록한다.


#### 7.3.1 식물 관리 콘텐츠 변경 이력 목록 조회

운영 관리자가 웹 관리자 화면의 식물 관리 콘텐츠 상세에서 해당 콘텐츠의 변경 이력을 시간순으로 조회하는 기능이다. 각 이력에는 변경 일시와 변경한 관리자를 표시하여 콘텐츠 변경 경위를 추적할 수 있으며, 콘텐츠 수정이나 복원 기능은 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 운영 관리자 | **기기**: 웹 관리자 화면

**개발 준비 슬롯**
- **선행조건**: - 운영 관리자가 웹 관리자 화면에 로그인하고 변경 이력을 조회할 식물 관리 콘텐츠가 존재한다.
- **트리거**: - 운영 관리자가 식물 관리 콘텐츠 상세 화면에서 변경 이력 조회를 선택한다.
- **동작**: - 시스템은 선택한 식물 관리 콘텐츠에 연결된 변경 이력을 조회한다.
  - 시스템은 변경 이력을 최신 변경 건부터 시간순으로 정렬하여 제공한다.
- **결과**: - 운영 관리자는 각 변경 건의 변경 일시와 변경한 관리자를 확인할 수 있다.
- **예외**: - 변경 이력이 없으면 아직 기록된 변경 이력이 없음을 표시한다.
  - 변경 이력 조회에 실패하면 오류 상태와 다시 시도 방법을 안내한다.
- **표시**: - 변경 이력 목록에는 각 변경 건의 변경 일시와 변경한 관리자 이름을 표시한다.
  - 변경 이력이 없을 때는 빈 상태 안내를 표시한다.
  - 변경 이력을 불러오는 동안에는 진행 상태를 표시한다.
- **권한 & 접근**: - 운영 관리자만 식물 관리 콘텐츠의 변경 이력을 조회할 수 있다.
  - 콘텐츠 관리자는 이 기능에서 다른 관리자의 변경 이력을 조회할 수 없다.
- **비즈니스 규칙**: - 변경 이력은 대상 식물 관리 콘텐츠별로 분리하여 조회한다.
  - 변경 이력은 콘텐츠의 현재 공개 또는 비공개 상태와 관계없이 운영 관리자가 조회할 수 있다.
  - 변경 이력 조회 기능은 콘텐츠 내용을 수정하거나 이전 버전으로 복원하지 않는다.
- **데이터**: - 변경 이력 데이터에는 변경 이력 식별자, 대상 콘텐츠 식별자, 변경 일시, 변경한 관리자 식별자와 관리자 표시명을 저장한다.
  - 변경 이력 조회 기록에는 조회한 운영 관리자 식별자, 대상 콘텐츠 식별자와 조회 시각을 저장한다.

## 8. 사용자 데이터 보호 및 계정 기반 동기화
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

사용자는 자신의 등록 식물, 관리 기록, 미니홈피 꾸미기 정보가 계정에 안전하게 연결되어 기기를 변경해도 이어서 이용할 수 있어야 한다. 식물 사진과 위치 정보는 식별 및 날씨 안내에 필요한 범위에서만 사용자 동의 후 처리하며, 사용자가 자신의 데이터와 권한을 관리할 수 있도록 한다.

**수용 기준:**
```
1. ○ 사용자가 계정에 로그인한 뒤 다른 모바일 기기에서도 자신의 등록 식물, 관리 기록 및 미니홈피 정보를 확인할 수 있다.
2. ○ 식물 사진 제출 전 사진 처리 목적이 안내되며, 위치 정보는 사용자 동의를 받은 경우에만 날씨 기반 안내에 사용된다.
3. ○ 사용자가 앱 설정에서 위치 정보 권한을 철회하거나 날씨 안내 지역을 직접 변경할 수 있다.
4. ○ 사용자가 자신의 계정 및 연결된 식물·관리·꾸미기 데이터 삭제를 요청할 수 있으며, 삭제 범위와 완료 상태가 안내된다.
```


### 8.1 계정 로그인 및 데이터 동기화
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**기능의 근거**: 사용자가 기기를 변경해도 자신의 등록 식물, 관리 기록, 미니홈피 꾸미기 정보를 이어서 이용할 수 있어야 한다.

일반 사용자는 계정에 로그인하여 등록 식물, 관리 기록, 미니홈피 정보를 계정에 연결하고 다른 모바일 기기에서도 이어서 확인한다. 이 기능은 계정 기반 데이터 동기화 범위를 다루며, 개별 식물 관리와 미니홈피 편집 흐름은 포함하지 않는다.

**개발 준비 슬롯**
- **선행조건**: - 사용자가 이용할 계정을 보유하고 로그인할 수 있다.
- **트리거**: - 사용자가 모바일 앱에서 로그인을 완료한다.
  - 사용자가 다른 모바일 기기에서 동일한 계정으로 로그인한다.
- **동작**: - 시스템이 로그인한 계정에 연결된 등록 식물, 관리 기록, 미니홈피 정보를 조회한다.
  - 시스템이 조회한 정보를 로그인한 모바일 기기에 동기화한다.
- **결과**: - 사용자가 다른 모바일 기기에서도 자신의 등록 식물, 관리 기록, 미니홈피 정보를 확인할 수 있다.
- **예외**: - 동기화 중 네트워크 오류가 발생하면 마지막으로 동기화된 정보를 유지하고 재시도를 안내한다.
- **표시**: - 로그인 및 동기화 진행 상태와 실패 상태를 사용자에게 표시한다.
- **권한 & 접근**: - 로그인한 사용자는 자신의 계정에 연결된 데이터만 조회할 수 있다.
  - 비로그인 사용자는 계정 기반 동기화 데이터에 접근할 수 없다.
- **비즈니스 규칙**: - 동일 계정으로 로그인한 모바일 기기 간에 계정 연결 데이터를 동기화한다.
- **데이터**: - 계정은 등록 식물, 관리 기록, 미니홈피 정보와 연결된다.


#### 8.1.1 계정 로그인 및 사용자 데이터 불러오기

일반 사용자가 모바일 앱에서 자신의 계정으로 로그인하여 계정에 연결된 식물, 관리 기록, 미니홈피 데이터를 이용할 수 있게 하는 기능이다. 로그인 성공 후 해당 계정의 데이터 동기화를 시작하는 진입 단계까지만 다루며, 기기 간 데이터 충돌 해결은 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

- **선행조건**: - 사용자가 이용할 계정을 보유한다.

- **트리거**: - 사용자가 모바일 앱에서 로그인을 선택한다.
- **동작**: - 사용자는 자신의 계정 인증 정보를 입력하여 로그인을 요청한다.
  - 시스템은 입력한 인증 정보를 확인하고 로그인한 계정을 식별한다.
  - 시스템은 로그인 성공 후 해당 계정에 연결된 데이터 동기화를 시작한다.
- **결과**: - 로그인한 사용자는 자신의 계정에 연결된 식물, 관리 기록, 미니홈피 정보를 조회할 수 있다.

- **예외**: - 인증 정보가 일치하지 않으면 로그인에 실패했음을 안내하고 다시 입력할 수 있게 한다.

  - 로그인 처리 중에는 진행 상태를 표시한다.

- **권한 & 접근**: - 로그인한 사용자는 자신의 계정에 연결된 데이터만 조회할 수 있다.

- **비즈니스 규칙**: - 로그인에 성공한 뒤에만 계정에 연결된 개인 식물, 관리 기록, 미니홈피 정보를 불러온다.

- **데이터**: - 로그인 상태 데이터에는 사용자 식별자, 인증 상태, 로그인 시각, 마지막 동기화 시각을 저장한다.

#### 8.1.2 다른 기기에서 계정 데이터 동기화

> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 기존 기기에서 계정에 연결된 식물, 관리 기록 또는 미니홈피 데이터를 보유한다.
  - 사용자가 다른 모바일 기기에서 동일한 계정으로 로그인한다.
- **트리거**: - 사용자가 다른 모바일 기기에서 동일 계정의 로그인을 완료한다.

- **동작**: - 시스템은 계정에 연결된 등록 식물, 관리 기록, 미니홈피 정보를 조회한다.
  - 시스템은 조회한 최신 데이터를 로그인한 모바일 기기에 반영한다.
  - 사용자는 동기화가 완료된 뒤 다른 기기에서 이어서 식물 관리와 미니홈피 이용을 계속한다.
- **결과**: - 사용자는 다른 모바일 기기에서도 자신의 등록 식물, 관리 기록, 미니홈피 정보를 확인할 수 있다.
  - 동기화가 완료된 데이터는 해당 기기에서 각 기능의 최신 이용 상태로 제공된다.
- **예외**: - 동기화 중 네트워크 오류가 발생하면 마지막으로 동기화된 정보를 유지하고 재시도를 안내한다.
  - 일부 데이터 항목을 불러오지 못하면 이용 가능한 데이터는 표시하고 동기화 실패 항목을 안내한다.
- **표시**: - 앱은 데이터 동기화 진행 상태와 마지막 동기화 시각을 표시한다.
  - 동기화에 실패하면 실패 사유와 다시 시도 버튼을 표시한다.
  - 동기화가 완료되면 사용자가 최신 계정 데이터를 불러왔음을 안내한다.
- **권한 & 접근**: - 사용자는 로그인한 자신의 계정에 연결된 데이터만 다른 기기로 동기화할 수 있다.
  - 다른 사용자의 개인 식물, 관리 기록, 미니홈피 정보는 동기화 대상에 포함하지 않는다.
- **비즈니스 규칙**: - 동일 계정으로 로그인한 모바일 기기 간에 등록 식물, 관리 기록, 미니홈피 정보를 동기화한다.

### 8.2 사진 및 위치 정보 동의 관리
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**기능의 근거**: 식물 사진과 위치 정보는 식별 및 날씨 안내에 필요한 범위에서만 사용자 동의 후 처리해야 하며, 위치 정보 오류와 개인정보 보호 위험을 관리해야 한다.

일반 사용자는 식물 사진 처리 목적을 확인한 뒤 사진을 제출하고, 위치 정보 제공에 동의한 경우에만 날씨 기반 안내를 이용한다. 사용자는 앱 설정에서 위치 권한을 철회하거나 날씨 안내 지역을 직접 변경할 수 있으며, 위치 동의 없이도 식물 관리의 기본 기능을 이용할 수 있다.

**개발 준비 슬롯**
- **선행조건**: - 사용자가 식물 사진을 제출하거나 날씨 기반 안내를 사용하려고 한다.
- **트리거**: - 사용자가 식물 사진 제출을 요청한다.
  - 사용자가 날씨 기반 안내를 처음 사용하거나 앱 설정에서 위치 정보 설정을 변경한다.
- **동작**: - 시스템이 사진 제출 전에 사진 처리 목적을 안내한다.
  - 시스템이 위치 정보 사용 동의를 받은 경우에만 위치 정보를 날씨 기반 안내에 사용한다.
  - 시스템이 사용자의 위치 권한 철회와 날씨 안내 지역 직접 변경을 반영한다.
- **결과**: - 사진 처리 목적이 사용자에게 안내된 뒤 사진이 식별 처리에 사용된다.
  - 동의된 위치 또는 사용자가 직접 설정한 지역이 날씨 기반 안내에 사용된다.
- **예외**: - 위치 권한이 거부되거나 철회되면 현재 위치 대신 사용자가 직접 설정한 지역을 사용할 수 있도록 안내한다.
  - 위치 정보를 사용할 수 없어도 식물 식별과 도감 이용을 포함한 기본 관리 기능은 유지한다.
- **표시**: - 사진 처리 목적과 위치 정보 사용 동의 안내를 표시한다.
  - 앱 설정 화면에 위치 권한 상태와 날씨 안내 지역 설정을 표시한다.
- **권한 & 접근**: - 위치 정보는 사용자가 동의한 경우에만 날씨 기반 안내에 접근하여 사용한다.
- **비즈니스 규칙**: - 식물 사진은 식별에 필요한 목적과 범위에서만 처리한다.
  - 위치 정보는 날씨 기반 안내에 필요한 범위에서만 사용한다.
- **데이터**: - 사용자 설정은 사진 처리 목적 안내 확인 여부, 위치 정보 사용 동의 상태, 날씨 안내 지역을 포함한다.


#### 8.2.1 식물 사진 처리 목적 안내 및 제출 확인

일반 사용자가 식물 식별을 위해 사진을 제출하기 전에 앱으로부터 사진 처리 목적을 확인하고 제출 여부를 결정하는 기능이다. 안내 확인은 사진 촬영·선택과 식별 분석 요청 사이의 고지 단계에 한정하며, 사진 식별 결과 제공과 개인 도감 등록은 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 카메라로 촬영하거나 사진 보관함에서 선택한 식물 사진을 식별 요청으로 제출하려고 한다.
- **트리거**: - 사용자가 사진 확인 화면에서 식별 요청 제출을 선택한다.
- **동작**: - 앱은 사진이 식물 종류 식별을 위해 처리됨을 사용자에게 안내한다.
  - 사용자는 안내 내용을 확인한 뒤 사진 제출을 계속하거나 취소할 수 있다.
  - 사용자가 제출을 확인하면 앱은 사진을 식별 분석 요청으로 전달한다.
- **결과**: - 사진 처리 목적을 확인한 사용자의 사진만 식별 분석 요청에 사용된다.
  - 사용자가 제출을 취소하면 식별 분석 요청을 생성하지 않는다.
- **예외**: - 안내 내용을 불러오지 못하면 사진 제출을 진행하지 않고 다시 시도할 수 있게 한다.
  - 사용자가 사진 제출을 취소하면 사진 확인 화면으로 돌아가 사진을 변경하거나 식별을 종료할 수 있게 한다.
- **표시**: - 사진 제출 전 화면에는 사진 처리 목적과 식별 분석에 사용됨을 알리는 안내를 표시한다.
  - 안내 화면에는 제출 계속 버튼과 취소 버튼을 표시한다.
- **권한 & 접근**: - 일반 사용자는 본인이 선택하거나 촬영한 사진에 대해서만 식별 요청 제출 여부를 결정할 수 있다.
- **비즈니스 규칙**: - 사용자가 사진 처리 목적 안내를 확인하기 전에는 식별 분석을 시작하지 않는다.
  - 사진 처리 목적 안내 확인 여부는 식별 요청별로 기록한다.
- **데이터**: - 사진 처리 안내 확인 데이터에는 사용자 식별자, 식별 요청 식별자, 안내 확인 여부, 확인 시각을 저장한다.


#### 8.2.2 현재 위치 기반 날씨 안내 동의 관리

일반 사용자가 날씨 기반 식물 관리 안내를 위해 현재 위치 사용에 동의하거나 동의를 철회하는 기능이다. 위치 정보는 동의한 경우에만 날씨 조회 기준으로 사용하며, 직접 지역 설정과 날씨 위험 판단·알림 발송은 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 날씨 기반 관리 안내를 처음 사용하거나 앱 설정에서 위치 정보 설정을 변경하려고 한다.
- **트리거**: - 사용자가 현재 위치 기반 날씨 안내 사용을 선택한다.
  - 사용자가 앱 설정에서 위치 정보 사용 동의 상태 변경을 선택한다.
- **동작**: - 앱은 현재 위치 정보가 날씨 기반 식물 관리 안내에 사용되는 목적을 안내한다.
  - 사용자는 위치 정보 사용에 동의하거나 거부할 수 있다.
  - 사용자는 앱 설정에서 기존 위치 정보 사용 동의를 철회할 수 있다.
  - 앱은 동의 상태 변경을 날씨 조회 기준에 반영한다.
- **결과**: - 위치 정보 사용에 동의한 경우 현재 위치를 날씨 기반 안내의 지역 기준으로 사용할 수 있다.
  - 위치 정보 사용 동의를 거부하거나 철회한 경우 현재 위치를 날씨 기반 안내에 사용하지 않는다.
- **예외**: - 운영체제 위치 권한이 거부되면 직접 지역을 설정하여 날씨 기반 안내를 이용할 수 있도록 안내한다.
  - 위치 정보 조회에 실패하면 현재 위치를 사용한 날씨 조회를 중단하고 직접 지역 설정 경로를 제공한다.
- **표시**: - 위치 정보 동의 화면에는 날씨 기반 식물 관리 안내를 위한 사용 목적을 표시한다.
  - 앱 설정 화면에는 현재 위치 권한 상태와 위치 정보 사용 동의 상태를 표시한다.
  - 위치 권한이 없거나 철회된 경우에는 직접 지역 설정으로 이동하는 안내를 표시한다.
- **권한 & 접근**: - 앱은 사용자가 명시적으로 동의하고 운영체제 위치 권한을 허용한 경우에만 현재 위치를 조회한다.
  - 일반 사용자는 자신의 위치 정보 사용 동의 상태만 변경할 수 있다.
- **비즈니스 규칙**: - 위치 정보는 날씨 기반 관리 안내에 필요한 범위에서만 사용한다.
  - 위치 정보 동의를 거부하거나 철회해도 식물 식별, 도감, 물 주기 관리 기능은 계속 이용할 수 있다.
  - 위치 정보 동의 철회 후에는 이후 날씨 조회에 현재 위치를 사용하지 않는다.
- **데이터**: - 위치 정보 설정 데이터에는 사용자 식별자, 위치 정보 사용 동의 상태, 운영체제 위치 권한 상태, 동의 또는 철회 시각을 저장한다.


#### 8.2.3 날씨 안내 지역 직접 설정 및 변경

일반 사용자가 현재 위치를 제공하지 않거나 다른 장소의 식물을 관리할 때 날씨 기반 안내에 사용할 지역을 직접 선택하고 변경하는 기능이다. 선택한 지역은 날씨 조회 기준으로 저장되며, 위치 권한 요청과 날씨 위험 판단 결과 제공은 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 날씨 기반 관리 안내를 이용하려고 한다.
- **트리거**: - 사용자가 위치 권한을 거부하거나 철회한다.
  - 사용자가 앱 설정에서 날씨 안내 지역 변경을 선택한다.
- **동작**: - 사용자는 날씨 기반 관리 안내에 사용할 지역을 검색하거나 목록에서 선택한다.
  - 사용자는 선택한 지역을 확인하고 저장한다.
  - 앱은 저장된 지역을 이후 날씨 정보 조회의 기준으로 사용한다.
- **결과**: - 사용자가 직접 설정한 지역이 날씨 기반 관리 안내의 조회 기준으로 저장된다.
  - 사용자는 위치 권한 없이도 설정한 지역 기준의 날씨 기반 안내를 이용할 수 있다.
- **예외**: - 지역 검색 또는 목록 조회에 실패하면 오류 상태와 다시 시도 방법을 안내한다.
  - 유효한 지역을 선택하지 않으면 저장을 진행하지 않고 지역 선택을 요청한다.
- **표시**: - 지역 설정 화면에는 지역 검색 입력란, 검색 결과 또는 선택 목록, 저장 버튼을 표시한다.
  - 앱 설정 화면에는 현재 날씨 안내 기준 지역을 표시한다.
  - 현재 위치 대신 직접 설정한 지역을 사용 중임을 표시한다.
- **권한 & 접근**: - 일반 사용자는 자신의 계정에 연결된 날씨 안내 지역만 등록하거나 변경할 수 있다.
  - 직접 지역 설정에는 기기 위치 접근 권한이 필요하지 않다.
- **비즈니스 규칙**: - 사용자가 직접 설정한 지역은 위치 권한이 없거나 위치 정보 사용 동의를 철회한 경우에도 날씨 조회 기준으로 사용할 수 있다.
  - 사용자가 지역을 변경하면 이후 날씨 기반 안내는 새로 저장한 지역을 기준으로 제공한다.
- **데이터**: - 날씨 안내 지역 데이터에는 사용자 식별자, 선택한 지역 식별값, 지역명, 설정 방식, 마지막 수정 시각을 저장한다.


### 8.3 계정 및 연결 데이터 삭제 요청
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**기능의 근거**: 사용자가 자신의 계정과 데이터에 대한 삭제를 요청하고 처리 상태를 확인할 수 있어야 개인정보를 관리할 수 있다.

일반 사용자는 자신의 계정과 연결된 식물, 관리, 꾸미기 데이터의 삭제를 요청하고 삭제 범위와 완료 상태를 확인한다. 이 기능은 사용자가 자신의 데이터 처리를 통제하도록 하며, 개별 식물만 삭제하는 관리 기능은 포함하지 않는다.

**개발 준비 슬롯**
- **선행조건**: - 사용자가 삭제를 요청할 계정으로 로그인되어 있다.
- **트리거**: - 사용자가 앱 설정에서 계정 및 연결 데이터 삭제를 요청한다.
- **동작**: - 시스템이 삭제 대상 범위를 사용자에게 안내한다.
  - 시스템이 사용자 확인 후 계정과 연결된 식물, 관리 기록, 미니홈피 꾸미기 데이터를 삭제 요청으로 처리한다.
  - 시스템이 삭제 처리 완료 상태를 사용자에게 안내한다.
- **결과**: - 사용자가 계정 및 연결 데이터의 삭제 범위와 완료 상태를 확인할 수 있다.
- **예외**: - 삭제 처리에 실패하면 데이터를 유지하고 실패 상태와 재시도 방법을 안내한다.
- **표시**: - 삭제 확인 화면에 삭제 대상 범위와 주의 사항을 표시한다.
  - 삭제 요청 및 완료 상태를 사용자에게 표시한다.
- **권한 & 접근**: - 로그인한 사용자는 자신의 계정과 연결된 데이터에 대해서만 삭제를 요청할 수 있다.
- **데이터**: - 삭제 요청은 요청 계정, 요청 일시, 삭제 대상 범위, 처리 상태를 포함한다.


#### 8.3.1 삭제 대상 범위 확인 및 최종 확인

일반 사용자가 계정 삭제를 요청하기 전에 함께 삭제되는 계정, 등록 식물, 관리 기록, 미니홈피 및 꾸미기 데이터를 확인하고 최종 삭제 의사를 명시하는 기능이다. 사용자가 삭제 영향을 이해한 상태에서만 다음 삭제 요청 단계로 진행하도록 하며, 실제 데이터 삭제 처리와 완료 상태 안내는 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 삭제를 요청할 자신의 계정으로 모바일 앱에 로그인한다.
- **트리거**: - 사용자가 앱 설정에서 계정 및 연결 데이터 삭제를 선택한다.
- **동작**: - 시스템은 삭제 대상에 계정, 등록 식물, 관리 기록, 미니홈피 구성 및 꾸미기 아이템 관련 데이터를 포함해 안내한다.
  - 사용자는 삭제 범위와 복구 가능 여부를 확인한다.
  - 사용자는 최종 확인 행동을 통해 삭제 요청을 진행한다.
- **결과**: - 사용자는 삭제될 데이터 범위와 삭제 요청의 영향을 이해한 뒤 삭제 요청 여부를 결정할 수 있다.
  - 최종 확인한 사용자는 삭제 요청 처리 단계로 이동한다.
- **예외**: - 사용자가 최종 확인을 취소하면 삭제 요청을 생성하지 않고 설정 화면으로 돌아갈 수 있다.
  - 삭제 대상 정보를 불러오지 못하면 삭제 요청을 진행하지 않고 다시 시도 방법을 안내한다.
- **표시**: - 삭제 확인 화면에는 삭제되는 데이터 항목과 삭제 후 이용할 수 없게 되는 기능을 표시한다.
  - 삭제 확인 화면에는 취소 버튼과 최종 삭제 요청 버튼을 구분하여 표시한다.
  - 삭제 요청 전 사용자의 신중한 확인이 필요함을 안내한다.
- **권한 & 접근**: - 로그인한 사용자는 자신의 계정과 연결된 데이터에 대해서만 삭제 요청을 시작할 수 있다.
- **비즈니스 규칙**: - 사용자의 명시적인 최종 확인 없이 계정 또는 연결 데이터를 삭제 요청 상태로 변경하지 않는다.
- **데이터**: - 삭제 요청 확인 데이터에는 요청 계정 식별자, 삭제 대상 범위, 최종 확인 시각을 저장한다.


#### 8.3.2 계정 및 연결 데이터 삭제 요청 생성

일반 사용자가 최종 확인한 계정 삭제 요청을 시스템에 제출하고, 시스템이 정해진 삭제 정책에 따라 계정과 연결 데이터를 삭제 대상으로 등록하는 기능이다. 삭제 요청의 중복 생성을 방지하고 유예 기간 중 복구 가능 여부를 적용하며, 사용자에게 처리 완료 상태를 보여 주는 기능은 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자가 자신의 계정에 로그인한다.
  - 사용자가 삭제 대상 범위를 확인하고 삭제 요청을 최종 확인한다.
- **트리거**: - 사용자가 삭제 확인 화면에서 최종 삭제 요청 버튼을 선택한다.
- **동작**: - 시스템은 계정과 연결된 식물, 관리 기록, 미니홈피 및 꾸미기 데이터를 삭제 요청 대상으로 등록한다.
  - 시스템은 삭제 요청의 처리 상태와 요청 시각을 저장한다.
  - 시스템은 삭제 정책에 따라 삭제 처리 또는 유예 기간을 시작한다.

  - 동일 계정의 삭제 요청이 처리 상태로 관리된다.
- **예외**: - 이미 처리 중인 삭제 요청이 있으면 중복 요청을 생성하지 않고 현재 처리 상태를 안내한다.
  - 삭제 요청 생성에 실패하면 기존 데이터는 유지하고 다시 시도 방법을 안내한다.

- **권한 & 접근**: - 로그인한 사용자는 자신의 계정에 대해서만 삭제 요청을 생성할 수 있다.

  - 처리 중인 삭제 요청이 있는 계정에는 중복 삭제 요청을 생성하지 않는다.
- **데이터**: - 삭제 요청 데이터에는 요청 식별자, 계정 식별자, 삭제 대상 범위, 요청 시각, 최종 삭제 예정일, 처리 상태를 저장한다.


#### 8.3.3 삭제 처리 완료 상태 안내

일반 사용자가 제출한 계정 및 연결 데이터 삭제 요청의 진행 상태와 최종 완료 여부를 확인하는 기능이다. 시스템은 처리 성공 또는 실패를 명확히 안내하여 사용자가 자신의 데이터 삭제 결과를 알 수 있게 하며, 삭제 대상 선택과 실제 삭제 실행 로직은 포함하지 않는다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: 일반 사용자 | **기기**: 모바일 앱

**개발 준비 슬롯**
- **선행조건**: - 사용자의 계정 및 연결 데이터 삭제 요청이 생성되어 있다.
- **트리거**: - 사용자가 삭제 요청 상태 화면에 진입한다.
  - 시스템이 삭제 요청의 처리 상태를 변경한다.
- **동작**: - 시스템은 삭제 요청의 접수, 처리 중, 완료 또는 실패 상태를 조회한다.
  - 시스템은 삭제가 완료된 경우 삭제된 데이터 범위와 완료 시각을 사용자에게 안내한다.
  - 시스템은 삭제 처리에 실패한 경우 실패 상태와 다시 시도 또는 문의 방법을 안내한다.
- **결과**: - 사용자는 자신의 계정 및 연결 데이터 삭제 요청이 완료되었는지 확인할 수 있다.
  - 사용자는 삭제 실패 시 필요한 후속 행동을 확인할 수 있다.
- **예외**: - 처리 상태를 불러오지 못하면 상태 확인이 지연되고 있음을 안내하며 다시 시도할 수 있게 한다.
  - 일부 데이터 삭제에 실패하면 전체 요청 상태와 실패한 처리 범위를 명확히 안내한다.
- **표시**: - 삭제 요청 상태 화면에는 현재 처리 상태, 요청 시각 및 최종 삭제 예정일 또는 완료 시각을 표시한다.
  - 삭제 완료 화면에는 삭제된 데이터 범위와 계정 이용 종료 사실을 표시한다.
  - 삭제 실패 화면에는 실패 상태와 다시 시도 또는 문의 경로를 표시한다.
- **권한 & 접근**: - 사용자는 자신의 계정에 생성된 삭제 요청 상태만 조회할 수 있다.
- **비즈니스 규칙**: - 삭제 완료 상태는 계정과 삭제 대상 연결 데이터의 처리 결과가 확정된 뒤에만 표시한다.
  - 삭제 처리 실패는 사용자 데이터가 삭제 완료된 것으로 표시하지 않는다.
- **데이터**: - 삭제 처리 이력에는 요청 식별자, 처리 상태, 상태 변경 시각, 완료 시각, 실패 사유를 저장한다.
